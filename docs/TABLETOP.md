# Tabletop RPG: генерируемые кампании

Отдельный режим поверх PR #23: собственные определения, GameState, механики,
история и UI. Narrative Runtime и его WorldState/WorldDelta здесь не используются.

## Начало игры

1. В общих настройках выбрать модель ведущего: Local, DeepSeek или OpenAI-совместимый API.
2. **Настольная RPG / RPG → Новая кампания**. Описать идею; подробный режим
   дополнительно задаёт жанр, тон, технологии, магию, масштаб и размер партии.
3. Сгенерировать структурированный мир. Проверить стартовую сцену и локации.
   Режим автора позволяет редактировать JSON с секретами и проверять его перед сохранением.
   Готовую CampaignDefinition можно импортировать без модели.
4. Создать героя: класс, вид, происхождение, распределение стандартного массива,
   навыки, набор снаряжения, внешность и личность. HP, AC и модификаторы считает сервер.
5. Начать игру. Свободный ввод использует **LLM DM**; кнопки механических действий
   работают без модели. Броски своего персонажа выполняются кнопкой **Бросить кубик**.
6. Разговаривать, брать задания, переходить между местами, искать объекты, открывать
   контейнеры, забирать предметы, сражаться и возвращать квестовые предметы.
7. **Расширить мир** создаёт новое место или другой ограниченный контент через
   проверяемые операции. Сохранение и ожидающий бросок переживают перезапуск сервера.

Для `compatible` задать на сервере `COMPATIBLE_BASE_URL` (полный API URL с `/v1`,
если этого требует сервис) и `COMPATIBLE_API_KEY`, затем перезапустить сервер.
Модель вводится в общих настройках; доступен запрос списка моделей.
Поле ключа DeepSeek не пересылается совместимому провайдеру. Все три провайдера
используют общий `llm.chat_stream`, обработку завершения, usage и ошибки.
Реальные модели могут выдать некорректное или слишком длинное определение:
такой ответ отклоняется до создания игры, автоматического LLM repair нет.

## Контракты и ответственность

| Модуль | Ответственность |
|---|---|
| `definitions.py` | CampaignDefinition, CharacterBuild, типизированные CampaignMutation |
| `catalog/`, `catalog.py` | Доверенный D20 Basic v2, классы, навыки, предметы, сложности |
| `compiler.py` | Ссылки, уникальность ID, достижимость, ruleset, сборка и расширение мира |
| `models.py` | Канонический GameState v2, контроллеры, очередь, команды, pending |
| `rules.py`, `dice.py` | Расчёт статов, попадания, урон, лечение, смерть, серверный RNG |
| `runtime.py`, `encounter.py` | Проверка команд, исследование, инвентарь, бой, реакции |
| `ai.py` | Considerations → BehaviorRegistry → UtilityScorer → Decision |
| `projection.py` | Public/Player Projection и отдельный релевантный DMProjection |
| `dm.py`, `generation.py` | Генерация определений, интерпретация, NPC-диалог, описание |
| `repository.py`, `migrations.py` | CAS, идемпотентность, текущий снимок, история, миграция v1 |
| `api.py` | HTTP-адаптер; состояние никогда не принимается как patch |

Генератор создаёт регионы, граф локаций, фракции и отношения, NPC/существ,
объекты, предметы, задания, секреты, столкновения и стартовую сцену.
Компилятор проверяет всё определение перед началом игры. Runtime не содержит
ID демонстрационного сценария; сценарии находятся только в тестах.

ActorControl хранит `PLAYER/AI/DM` и `player_id`. Бросок принадлежит актору и
контроллеру, а не выбранной карточке. Несколько локальных PC получают собственные
броски инициативы и ходы; AI-компаньоны и противники ходят автоматически.
Это пока одна локальная игровая сессия, не сетевой кооператив с авторизацией пользователей.

Отношения `ALLY/NEUTRAL/HOSTILE` определяются данными фракций. AI оценивает
атаку, сближение, бегство, уклонение, помощь, предметы, защиту союзника,
отход и рывок. Оценка не изменяет состояние; выбранная команда идёт через runtime.

## Правила и ограничения

D20 Basic v2 — ограниченная D&D-подобная система, не полная D&D 5e:
воин/разведчик 1-го уровня; человек/эльф/дварф; три происхождения; шесть
характеристик и стандартный массив. Каталог определяет наборы снаряжения,
навыки, спасброски, скорость, критические попадания и таблицу сложностей.

Есть action, bonus action (ограниченное восстановление), reaction (защита и
атака при выходе из досягаемости), движение, help, dodge, dash, disengage,
лечение, бессознательность, спасброски от смерти, победа/поражение/бегство.
Позиция одномерная; при одном перемещении предлагается первая доступная реакция PC.
Короткий отдых тратит кость здоровья и лечит `max(1, 5 + CON)`; долгий восстанавливает
живых участников и ресурсы. Полной магии и развития после первого уровня пока нет.

Сложность обычной проверки задаётся категорией из каталога. Для объекта его
определение имеет приоритет. Натуральные 1/20 автоматически влияют на атаки,
но не превращают невозможную проверку навыка в успех. Убеждение раскрывает только
разрешённое знание; принципиально недоступное требование получает отказ без броска.
Общая проверка записывает успех/провал и не создаёт произвольные последствия.

Предметы структурированы: ID, количество, экипировка. Оружие и броня меняют
рассчитанные параметры; расходник лечит; задания принимают предметы и выдают
объявленную награду один раз. Добыча столкновения открывается только после победы,
затем её нужно взять из контейнера. Бегство не выдаёт добычу.

## Границы LLM и скрытые сведения

Интерпретация получает релевантные текущему месту скрытые объекты, секреты и
намерения NPC. Игровые API, журнал, карта, replay и диагностика получают только
Public/Player Projection. Контекст NPC-ответа/описания содержит публичную информацию
и раскрытия, подтверждённые движком. Авторский редактор — отдельная поверхность
со спойлерами, а не игровой API.

LLM не может прислать HP, raw dice, произвольный StateDelta или инвентарь игрока.
CampaignMutation допускает только CreateLocation/NPC/Item/Quest/Encounter/Object/Faction,
ConnectLocations и RevealKnowledge с проверяемым открытым источником.
Операция не может заменить существующий ID; невалидное расширение полностью отклоняется.

Для этапов campaign_generation, content_generation, interpretation, npc_dialogue и
narration сохраняются статус, модель, длительность, токены и известная стоимость.
Ключи не попадают в tabletop-таблицы. Неизвестная цена/usage остаётся `null`.
Ответ HTTP выдаётся после завершения генерации; tabletop SSE/отмена ещё не реализованы.

## Сохранения

Текущий снимок не восстанавливается из истории при обычной загрузке. CAS ревизия и
ID запроса обеспечивают единственную фиксацию действия. Повтор запроса не бросает
кубики снова. Механика фиксируется до художественного описания: ошибка провайдера
не отменяет бросок, вместо него показываются события движка.

Rollback создаёт новую ревизию со снимком before. Replay читает проверенный снимок
без RNG/LLM. Повреждение history не ломает current; повреждённый снимок нельзя
использовать для replay/rollback. Миграция v1 сохраняет исходный JSON отдельно,
не меняет ревизию и сохраняет HP, очередь, ID ожидающего броска и старые атаки.

## Проверки

`python -m pytest -q` — полный backend suite, включая компилятор, контроллеры,
секреты, семантические DC, AI, несколько союзников/врагов, реакции, ловушки,
инвентарь, задания, генерацию, мутации, CAS, replay/rollback и миграцию v1.

`cd frontend && npm run build` — TypeScript и production bundle.
`npx playwright test tabletop.spec.ts` — desktop/mobile: генерация → герой →
диалог/задание → поиск → предмет → бой/движение/урон/лечение → добыча → завершение
задания → новый контент. Тест останавливает и заново запускает настоящий процесс
backend с той же SQLite, сравнивает pending и продолжает игру.

В автотестах подменяется только LLM stream и источник случайных чисел;
HTTP, компилятор, runtime, SQLite и интерфейс настоящие. Успешный mocked-тест
не подтверждает качество мира, созданного конкретной внешней моделью.
