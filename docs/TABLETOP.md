# Tabletop RPG: первый рабочий срез

Основание: PR #23 (`codex/runtime-v3`, `4f265d5`). Настольный режим подключён рядом
с интерактивной историей, не импортирует `engine`, `runtime_v3`, WorldState или
narrative extraction. Игровые сохранения и таблицы истории разделены.

## Как играть

1. Нажать **Настольная RPG** (на телефоне **RPG**) в верхней панели.
2. **Новая игра** → семь шагов → **Начать приключение**.
3. **Осмотреть сундук** → **Бросить кубик**. Успех открывает скрытое знание.
4. **Начать бой** → бросок инициативы. NPC ходят автоматически по правилам.
5. **Атаковать** → бросок атаки → при попадании отдельный бросок урона.
6. **Закончить ход** → NPC → новый раунд. Можно двигаться, уклоняться и делать рывок.
7. Перезагрузка восстанавливает кампанию, очередь и ожидающий бросок.

Для свободного ввода включить **LLM DM**. Используются выбранные в общих настройках
игры провайдер/модель/Thinking и сохранённый ключ. Сначала можно нажать
**Осмотреться**, чтобы получить описание модели. Без модели работают все
кнопки; текстовые сокращения: «осмотреться», «осмотреть сундук», «начать бой»,
«закончить ход». Произвольный текст без модели даёт понятную ошибку без изменений.

## Границы первого ruleset

D20 Basic — намеренно ограниченная D&D-подобная система, **не полная редакция D&D**.
Есть воин 1-го уровня, шесть характеристик, владение навыками/спасбросками,
проверки, преимущество/помеха в DiceEngine, атаки, критические попадания,
урон/лечение, смерть/потеря сознания, инициатива, очередь, уклонение, рывок,
одномерное перемещение и отдых. Короткий отдых тратит кость здоровья и
восстанавливает фиксированные `5 + CON` (минимум 1) HP; долгий восстанавливает
HP и кости здоровья. Это явно упрощённые правила.

Первый готовый сценарий: двор заставы, скрытое знание за сундуком, гоблин,
необязательный спутник Терон. В мастере можно изменить описание мира,
названия кампании/героя и биографию. Описание не генерирует новую географию
или механические объекты. Setting, Campaign и GameState — разные модели;
кампания хранит собственный снимок setting/ruleset.

Пока нет заклинаний, редактора классов, уровневого развития, полноценной карты,
атаки реакцией, бонусных действий, команд спутникам, генератора ruleset/мира и
библиотеки шаблонов в UI. Поля bonus/reaction зарезервированы, UI явно помечает
их как следующий этап. Нестандартная проверка без известного объекта фиксирует
успех/провал, но не создаёт произвольные предметы/эффекты. Выпавшие NPC не
выполняют спасброски от смерти; игрок выполняет. Полная система эффектов,
социального AI и реакций требует дальнейшего расширения контрактов.

## Ответственность модулей

| Модуль | Ответственность |
|---|---|
| `models.py` | Отдельный GameState, ruleset, setting/campaign, лист, команды и pending roll |
| `dice.py` | Серверный SystemRandom; внедряемый RNG; raw/selected/modifier/total |
| `rules.py` | Производные модификаторы, проверки, атаки, HP, смерть и лечение |
| `encounter.py` | Инициатива, бюджет действий/перемещения, очередь и NPC |
| `ai.py` | Доступные действия, utility scores и выбор без LLM |
| `runtime.py` | Команда → независимая копия → полная валидация → события |
| `projection.py` | Белый список player-visible состояния |
| `dm.py` | Отдельный контекст, интерпретация и описание, общий provider/usage/local lock |
| `repository.py` | Собственные SQLite-таблицы, CAS, журнал, replay и откат |
| `api.py` | `/api/tabletop`; ни один endpoint не возвращает canonical/DM state |

LLM получает JSON Schema допустимой команды. Поля `hp`, `damage`, `actor`,
`patch` и произвольные типы запрещены. Движок дополнительно проверяет текущую
очередь, бюджет, цель, оружие, расстояние, capability и ожидающий бросок.
Для известного объекта DC берётся из сценария, а не из ответа модели.
Интерпретация — максимум один вызов; описание — максимум один. NPC не вызывают LLM.

Контекст описания и интерпретации строится из публичной проекции: секреты,
скрытые DC, HP/AC противника, внутренние знания/цели/отношения NPC отсутствуют.
Новый факт попадает в PlayerKnowledge только после успешного решения движка.
Текст модели не применяется к состоянию. Как и любая свободная генерация,
описание может быть неточным; подтверждённые механические события и броски
остаются в журнале отдельно. Никакой текстовый фильтр не выдаётся за гарантию
фактической точности LLM.

## Атомарность и восстановление

- `tabletop_games.state_json` — current source of truth.
- `tabletop_history` — отдельные before/after, их SHA-256, события и текст.
- `BEGIN IMMEDIATE` проверяет revision, записывает историю и current одной транзакцией.
- Уникальный `(game_id, request_id)` и fingerprint предотвращают повторное применение.
- Pending содержит серверный ID; клиент не передаёт raw/total результата.
- На конкурентных запросах только один CAS может зафиксировать изменение.
- Бросок сначала фиксируется, описание добавляется отдельно. При ошибке провайдера
  показываются события движка; повторный запрос не перебрасывает кубики.
- `/replay/{revision}` читает проверенный снимок без LLM/RNG. Это snapshot replay,
  не повторное исполнение интерпретации команд.
- Откат создаёт новую ревизию и восстанавливает before последнего действия;
  история не удаляется. Откат броска возвращает его pending: новый бросок после
  явного отката считается новым действием. Повтор отката отменяет предыдущий откат.
- Повреждённая история не участвует в обычной загрузке current; повреждённый снимок
  нельзя восстановить через rollback/replay.
- Общая SQLite-инфраструктура переиспользуется по пути БД. Таблицы Narrative
  не изменяются настольным runtime. Ключи не сохраняются в tabletop таблицах.

LLM stream читается общим клиентом провайдера, HTTP-ответ первого среза возвращается
целиком после генерации; прогрессивный tabletop SSE/отмена генерации пока не добавлены.
Для запросов сохраняются stage, статус, длительность, input/output/cached tokens и
снимок существующего общего тарифа. Неизвестные значения остаются `null`.

## Проверка

`python -m pytest -q` — общий backend suite, включая `tests/test_tabletop.py`:
броски, модификаторы, сохранения, критические попадания, HP/смерть, очередь,
AI, туман войны, недопустимые команды LLM, CAS, атомарный отказ, повтор запроса,
restart pending, повреждение history, rollback/replay, fallback DM и полный
exploration → check → roll → encounter → attack → damage → NPC → round.

`cd frontend && npm run build` — TypeScript и production bundle.
`npx playwright test tabletop.spec.ts` — реальные backend/UI на desktop/mobile.
Реальный ответ внешнего провайдера не входит в автоматический тест: контракт
провайдера проверяется подменённым stream, а механики — настоящим runtime.
