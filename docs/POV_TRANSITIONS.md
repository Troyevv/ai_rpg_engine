# Полноценные переходы POV

`POST /api/saves/{id}/actor` теперь принимает `actor_id`, `revision`, `config`,
необязательный `api_key` и `source_turn_id`. Возвращается job, который использует
обычный SSE и ту же пару ведущий/обработчик состояния. Новый тип хода — `pov`.

Смена роли атомарна с успешным вступлением. `before_json` содержит состояние до
переключения для отката; `memory_before_json` — подготовленную точку нового POV
для точной перегенерации. Неудачная/остановленная генерация не меняет канон.
Повторная обработка сохраняет target actor, источник и исходные промпты.

Для вступления берутся последняя точка персонажа, его факты, отношения, память,
открытые линии и текущая сцена. Вступление останавливается перед решением игрока;
обработчик возвращает шесть действий. Своё действие остаётся доступным.
Если передан `source_turn_id`, он должен быть последней канонической закулисной
сценой, а actor — её участником. `source_node_id` фиксируется в переходе;
опорой служит сохранённая точка именно этой сцены, не новая случайная ситуация.

После «Мир без ГГ» доступны возврат к основному герою и выбор участника.
Возврат тоже запускает POV-вступление, включая случай, когда контролируемый ID
не меняется: мир после фонового события уже мог измениться.

## Правило времени

Все новые сцены принадлежат одной последовательной временной шкале. Неявных
флешбэков и параллельных сцен в этой реализации нет. `world_clock.minute` — число
минут с начала условного первого дня; `last_event_time` — человекочитаемый вид
`День N HH:MM`. Новая сцена не может иметь время меньше текущего.

Старые `HH:MM`, русские сокращения/названия дней недели и `День N HH:MM` читаются
без потери старых снимков. Для старого времени без дня берётся текущий день;
переход через полночь требует явного следующего дня. Если времени вообще не
было, используется нулевая точка День 1 00:00; контекст сообщает её ведущему.

`actor_scenes` сохраняет отдельные опорные точки. При переключении старая точка
остаётся в `pov_transition.anchor`, но сцена вступления синхронизируется с текущим
временем мира. Например, после Пт 20:30 нельзя вернуться к сцене героя в Пт 19:50.
Модель должна показать его ситуацию сейчас, не принимать важные решения за него
и не пересказывать ему неизвестные фоновые события. Если JSON пытается вернуть
время назад, ход отклоняется без изменения состояния; готовый текст остаётся
черновиком для повторной обработки.

Это согласованная шкала порядка событий, не полноценный календарь с часовыми
поясами. Старые произвольные даты не считаются надёжным числовым временем.

## Совместимость

Состояние остаётся JSON в SQLite, снимки — в существующих jobs/вариантах. Новая
таблица для параллельной игровой системы не создаётся. Старые сейвы читаются с
fallback для часов и actor_scenes; первая успешная сцена сохраняет нормализованные
часы. Старые before/after JSON и текстовые сообщения не переписываются.
Регенерация повторяет исходное вступление с тем же актёром/памятью; смена варианта
восстанавливает весь снимок, а последующие ходы требуют отката с архивированием.
