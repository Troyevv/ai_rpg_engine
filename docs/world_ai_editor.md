# AI-редактор черновика (#173)

В существующем редакторе выберите «Автор мира» → «AI-редактор мира».
Свободная инструкция может затронуть несколько связанных сущностей.
Задание сначала готовит и проверяет отдельный пакет. Откройте группы изменений,
изучите значения до/после, замечания и ручные конфликты. «Применить пакет…»
открывает подтверждение. Отказ не меняет кандидат. Откат доступен через
«Ещё» → «История версий» → «Восстановить»; восстановление само создаёт версию.

## Контракт

- `POST /api/workspaces/{wid}/draft/edits`: revision, text, request_id, config,
  credentials, optional budget. Нет ограничения длины художественной инструкции;
  существующий транспорт проверяет реальный размер контекста до платного вызова.
- `GET /api/workspaces/{wid}/draft/edits`: авторская история предложений, полный
  diff, ревизия основы, конфликты, review и фактически учтённые запросы/расходы.
  Это явная авторская поверхность, как существующие draft/raw и author=true.
  В обычный draft/player response эти данные не включаются.
- `POST /api/workspaces/{wid}/draft/edits/{jid}`: accept/reject, revision,
  accept_conflicts, accept_warnings. Сервер повторно проверяет основу и пакет.
- Существующие `/draft/resume`, `/jobs/{jid}/stop`, `/draft/raw` сохраняют
  provider abstraction, credentials, отмену, фрагменты ответа, бюджет и диагностику.

Хранение — существующие preparation_jobs.response_journal, llm_requests и
append-only document_versions. Схема SQLite не меняется. Ни предложения,
ни отклонённые/прерванные ответы не меняют world_draft или игровые snapshots.
При принятии одна транзакция записывает версию и решение. Повторное подтверждение
идемпотентно; старое подтверждение не перематывает последующие версии.

`request_id` привязан к запросу в workspace; резервирование потребляет revision.
Поэтому быстрый ответ, повтор HTTP и конкурентные клики не создают вторую
оплаченную задачу. После ручной правки, восстановления версии или нового запроса
старый preview непригоден для применения. Resume не подменяет замороженную основу.
После Start Game создание, продолжение и применение AI-редакций запрещены.

Общий draft_changes из #172 расширен удалениями только в editing-режиме.
Индексы списков относятся к исходной версии; удаления выполняются после остальных
операций. Ссылки проверяются после всего пакета. Перед применением сохраняются
защиты времени, камеры, управления, player agency и серверного provenance.
Ремонт использует существующие адресные коррекции (до двух) и semantic review /
repair (до двух), без повторной генерации мира. Неразрешённые конфликты и semantic
blockers запрещают применение; рекомендации требуют явного подтверждения.

Предыдущие manual_paths сохраняются и перебазируются по ID при удалении карточек.
Удалённые намеренно поля остаются в истории исходной версии/задания, а не висят
невалидными pointers в новом кандидате. Принятая инструкция записывается в
`authoring.editor_instructions`; последующие семантические проверки получают её
с более высоким приоритетом, чем прежние модельные детали.

## Границы

- Редактор не редактирует уже начатую игру и не переносит в неё изменения черновика.
- Управление, камера, время начала и настройки — защищённый контекст; для их
  изменения остаются существующие ручные формы. Будущие решения игрока не
  выполняются даже при генерации связанного пакета.
- Модель может ошибаться в литературной согласованности. Контролируемый provider
  в тестах доказывает lifecycle и инварианты, не качество живого DeepSeek.
- Неизвестные usage/cost остаются неизвестными; потерянный исход HTTP требует
  явного разрешения повтора. Полный контекст может потребовать большую модельную
  ёмкость; скрытой обрезки мира нет.
- #118 и редизайн #175 не используются. Файлы тестовых снимков/видео не входят в PR.
