# Narrative V3 — утверждённый эталон интерфейса

Этот каталог хранит неизменный эталон для задачи переработки Narrative и игрового телефона. Это отдельная ветка с материалами дизайна; продуктовый код в ней не изменён.

## Как открыть

1. Скачайте `narrative-reference-v3.zip` и распакуйте.
2. Откройте `narrative-reference-v3/dist/index.html` — это полноэкранный продукт.
3. `dist/review.html` показывает тот же продукт в desktop/tablet/mobile-контейнерах. Панель выбора устройства не входит в продукт.
4. Изучите `src/`, `docs/HANDOFF.md` и `README.md` внутри пакета. Шрифты и иконки включены, внешние ресурсы не нужны.

Для браузерной автоматизации можно запустить статический сервер: `python -m http.server 4173 --directory narrative-reference-v3/dist`.

## Правила переноса

- Визуальный источник истины — работающий `dist/index.html` и исходники V3. Требуется точное воспроизведение, включая телефон, панели, состояния и адаптивность.
- Рабочую ветку реализации создавать от актуального `master`, а материалы брать из этой ветки. Не откатывать продукт к базе эталона и не мёрджить ветку с архивом ради доступа к файлам.
- База проверки состава функций эталона: `2597f1a3656296c6de945ceb425fda3c2cce1373`, включая PR #271. При более новом master сохранять актуальные возможности.
- Runtime, API, хранилище, Chat/Narrative и реальные обработчики остаются владельцами бизнес-логики. Не встраивать готовый HTML или iframe вместо React-компонентов.
- Локальные массивы, подготовленные ответы, таймеры, фиктивный usage и ограничения демонстрации не переносятся в production.
- Уточнение после сверки с master: в демо закрытие телефона заканчивает демонстрационный звонок. В production закрытие/сворачивание UI и явное завершение CallScene — разные операции. Сохранить существующий lifecycle, lock, operation_id, revision и изоляцию состояния.
- Перечень адресатов и доступные каналы определяются существующими capabilities. Живого NPC нельзя исключать только из-за отсутствия сохранённого контакта; это не разрешает раскрывать его скрытые знания, переписки или координаты.
- Полные требования, границы, приёмка и условия PR задаются связанной GitHub-задачей; она уточняет ограничения демонстрации и имеет приоритет над общими заметками HANDOFF.

## Статус самого эталона

Эталон проверен в браузере на desktop, tablet и mobile до 320px; 26 DOM smoke-сценариев прошли. Это не заменяет production E2E и визуальную приёмку. Настоящая экранная клавиатура iOS/Android и все сочетания тем/длинного контента в эталоне не проверены.

Ветка содержит только материалы для реализации и не является PR с готовыми изменениями приложения.
