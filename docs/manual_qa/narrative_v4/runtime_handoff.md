## Contract / compatibility

New DOB writers use `Character.birth_date_provenance`. The existing
`birth_provenance` remains the Runtime birth process/event field. The common
`birth_identity` reader recognizes historical DOB-only source/signature/twin
metadata without treating it as gameplay birth. Unknown provenance fails closed;
a pregnancy reference must identify that born child. Mixed legacy metadata keeps
real birth protection. Manual DOB writes never overwrite real birth metadata.

Old v3 snapshots are interpreted on a private copy, including cached migrations,
retry before snapshots and variants. If old DOB editing overwrote a real birth,
only an existing unambiguous born pregnancy/child reference can restore its process
link; no event, fact or Knowledge is fabricated. Raw historical JSON stays intact.
No calendar presets are silently applied to old saves. Users need only reopen the
save after updating, then retry state processing for a saved unapplied narrative.

`legacy_snapshot.json` is a **local baseline replica**, generated by real
import → confirm at `58c8e2967470b5c9f461d887016387f2f29d2142`, not the user's SQLite.
The provided generation E5 journal is not a gameplay extraction log. No original
user gameplay job/raw extraction or paid provider run is claimed here.
