# Ручные сценарии base v2

Перед каждым независимым сценарием выполните reset по [README](README.md).
Запишите commit SHA, fixture version, checkpoint, DB/save ID, провайдер/модель,
фактический результат и номер проблемного хода. Реальную LLM не сравнивайте по
точному тексту; проверяйте семантику и canonical состояние.

## B1. Загрузка, повторный reset, изоляция

**Старт:** base, без ходов. В той же dev-БД есть отдельный обычный мир и его
прохождение; запишите их IDs, состояние и историю. Не используйте рабочую БД игрока.

**Действия:** загрузите fixture; проверьте таблицы README через «Автор мира» в
созданном черновике и игровой инспектор. Начните тестовую игру, дождитесь сохранения
ответа. Выполните команду reset ещё раз; откройте новое прохождение по выданному ID.

**Результат:** новый save имеет 12 персонажей, 6 мест, время 540, Кирилла под
управлением, ровно трёх начальных участников, пустую историю ходов и точные начальные
отношения/знания. «Автор мира» открывает соответствующий workspace без ошибки.

**Отрицательный инвариант:** прежнее QA прохождение, обычный save и посторонние
черновики не изменены и не удалены; выбор в уже открытой вкладке не переключён сам.

**Save/reload:** обновите страницу каждого из двух QA saves; в одном остаётся
пройденный ход, второй остаётся начальным. **Откат/ветка:** reset не является
rollback или сменой варианта; прежняя история сохраняется отдельно.

## B2. Обычный ход → сохранение → reload → следующий ход

**Старт:** base; настроен рабочий провайдер; нет активной генерации.

**Действия:** нажмите начало игры, дождитесь завершения. Отправьте
«Рассмотреть фотографии и спросить Тимура, где снят оригинал карты».
Дождитесь сохранения; запишите сцену, время, участников, состояние и историю ходов.
Обновите страницу (при необходимости перезапустите dev-сервер на той же БД).
Отправьте «Попросить Тимура показать наиболее чёткий снимок».

**Результат:** сохранённые ход и choices восстановлены; следующий ход успешно
добавлен. Камера и позиции персонажей согласованы с принятым final_scene, время
не идёт назад. Без перехода в другое место исходный разговор остаётся в доме.
Если модель описала переход, проверяйте согласованность с canonical-последствием,
а не требуйте неизменности сцены вопреки рассказу.

**Отрицательный инвариант:** контроль остаётся у Кирилла; NPC не появляются в
камере только потому, что перечислены в мире. Runtime не назначает Кириллу новые
цели или обязательства без явного выбора игрока. Тайна Олега не становится знанием
Кирилла из-за самого факта существования в World Truth.

**Save/reload:** второй обычный ход тоже переживает повторное открытие.
**Откат/ветка:** откатите второй ход — snapshot должен вернуться к состоянию
после первого; затем другой ввод продолжает историю с этой точки. Выбор варианта
отдельно проверяется в B4. Автоматический smoke фиксирует elapsed_minutes=1:
start + первый turn дают 542, следующий turn — 543; для реальной LLM минуты
зависят от прошедших действий, эти числа не являются manual requirement.

## B3. World Truth, частные знания и направленные отношения

**Старт:** свежий base до генерации. Только `qa_oleg:qa_private_letter` знает о
письме. Кирилл, Вера и Тимур знают `qa_library_open`; у остальных такого знания нет.

**Действия:** сравните «Автор мира» и player preview черновика. В авторском режиме
проверьте письмо и его владельца; в player preview письмо отсутствует. Проверьте
отношения Кирилл → Вера и Вера → Кирилл. Начните игру и попросите обсудить фотографии,
не сообщая никому о письме и не меняя POV/контроль.

**Результат:** автор видит canonical факт и четыре начальные Knowledge записи;
у обратных отношений разные trust/affection, согласно README. После обычного
разговора knowledge о письме не добавлено без grounded acquisition. Проверяйте
`get_snapshot()` для истины и знаний; GM-only context может содержать тайны и сам
по себе не доказывает, что Character их узнал. Полный игровой инспектор — также
не player preview черновика.

**Отрицательный инвариант:** публичность факта не равна автоматической рассылке
всем Characters; обратное отношение не зеркалируется. Не путайте отсутствие
Knowledge записи с новой придуманной «устаревшей»/«исправленной» записью (#76).

**Save/reload:** после повторного открытия знания и направления отношений
совпадают с сохранёнными. **Откат/ветка:** после отката разговора знания и отношения
возвращаются к его before snapshot; непройденные варианты не влияют на текущий state.

## B4. Регенерация, выбор варианта, откат

**Старт:** base → start → один обычный turn; оба успешно сохранены.
Зафиксируйте snapshot до последнего хода и после него, IDs текущего варианта.

**Действия:** регенерируйте последний ответ; дождитесь сохранения. Выберите
предыдущий вариант стрелкой под сценой. Обновите страницу. Откатите последний ход.
Сделайте новый обычный ход от восстановленной точки.

**Результат:** после выбора старого варианта текущий snapshot в точности равен
его сохранённому after (включая history pointer). После отката — исходному before.
Новый ход успешно сохраняется. Revision/служебные timestamps могут увеличиваться.

**Отрицательный инвариант:** состояния разных вариантов не смешиваются; начальный
immutable world и другой save остаются неизменными. Регенерация использует
сохранённый контекст исходного хода, что видно в штатной диагностике запросов.

**Save/reload:** выбранный вариант остаётся активным после обновления.
**Откат/ветка:** для варианта более раннего хода штатно требуется откат зависимых
ходов; проверьте архив после подтверждения. Именованные ветки не реализованы,
создавать их для этого сценария не нужно.
