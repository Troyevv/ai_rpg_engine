# #39: проживание, география, организации и роли

Используйте существующий loader #78 и отдельную dev-БД:

```bash
RPG_DEV_TOOLS=1 python scripts/narrative_test_world.py --checkpoint residence-roles
RPG_DB_PATH="$PWD/data/dev-narrative-v4.sqlite3" python -m uvicorn backend.main:app --host 127.0.0.1 --port 8010
```

Повтор loader создаёт новое прохождение/reset без изменения старого. Выберите возвращённый
save ID. `base` и прежние checkpoints не изменены. Старт: Кирилл дома (`qa_home`),
его проживание `qa_home_residence`, работа `qa_job` в `qa_restorers`; Ася учится
(`qa_pupil`, `qa_school`). Елена физически в `qa_garden` и живёт там, но Кирилл её
проживание не знает. `qa_academy` готова для проверки нового обучения.

Иерархия: `qa_realm` → `qa_north` / `qa_south` → `qa_north_city` /
`qa_south_city` → исходные здания; `qa_room` — дочерняя комната `qa_home`.

| Последовательность действий | Ожидаемое состояние |
|---|---|
| Start → обычный разговор → save/reload → следующий разговор | Состояние валидно; проживание и роли не исчезают, активны те же IDs |
| Перейти в комнату, затем съездить в Речной Посад | Меняется physical location; `qa_home_residence` и `qa_job` не меняются; коллеги не телепортируются |
| Явно установить завершённый переезд Кирилла в сад Елены с заменой старого дома | Новая residence с новым ID, старый `qa_home_residence` closed; since/until и даты соответствуют #37; работа не меняется |
| Вместо замены явно установить второе постоянное жильё | Две active residence; старый дом не закрыт |
| Установить новое обучение Кирилла в Академии, сохраняя работу | Два active roles, присутствие по-прежнему определяется камерой/movements |
| Завершить работу Кирилла увольнением | Closed только `qa_job`; обучение активно; старый работодатель и период сохранены |
| NPC Ася завершает школу, затем поступает в академию/ученичество, потом получает работу | Закрытые фазы школы и обучения + новая фаза; возраст не запускает переходы автоматически; нет обязательных ступеней |
| Изменить работодателя или программу обучения | Новая фаза + явно закрытая старая; старый institution/program не переписан |
| Переименовать Мастерскую, затем установить её закрытие | Один organization ID и история имени; связанные active роли закрыты с organization_closed; нет нового работодателя, переезда или автоматического Knowledge |
| Упомянуть известное место по явно записанному alias | Переиспользуется ID; нет дубликата. Неподтверждённый spelling variant требует canonical ID, а не fuzzy merge |
| Попытаться назначить `qa_home.parent_id=qa_room`, неизвестного parent или organization | Diagnostic и отклонение записи; остальные валидные изменения хода сохранены |
| Пригласить Елену без состоявшегося прибытия | Она остаётся в саду. Фактическое прибытие требует evidence; проживание не означает присутствие |
| Обсудить будущий переезд/школу/новую работу, не устанавливая результат | Только narrative/при необходимости #66; новой residence/role нет |
| Время/Time Skip без установленного перехода | Проживание и роли не меняются от времени или возраста; новых расписаний нет |

В «Мир» и карточке персонажа доступны известные проживания/роли и их история.
Кирилл видит свой дом, работу и школу Аси; не видит `qa_elena_residence`.
Новый факт сообщается через обычный witnessed informational event/Knowledge. Знание
старого дома/работы не раскрывает последующий переезд, увольнение или новое имя организации.
Проверить те же границы после смены POV/управления и на узком мобильном экране.

После каждого существенного перехода: reload → проверить записи → regenerate
(другая версия не наследует переход первой) → вернуть прежний variant → rollback.
В соседней ветке должны оставаться собственные роли, проживания, Knowledge и History.
При невалидной replacement запись старого дома/работы не должна закрыться частично.

Платные LLM-вызовы для CI не требуются. `tests/test_residence_roles.py` содержит
детерминированные payload-сценарии, настоящий start/turn/save/reload/regenerate/rollback
и sibling History branches. `frontend/e2e/residence.spec.ts` проверяет desktop/mobile.
Ручная история может отличаться: проверяйте canonical результат и diagnostics,
а не обязательную реплику модели. Полный контракт: `docs/residence-roles.md`.
