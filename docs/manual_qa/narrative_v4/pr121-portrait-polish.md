## Исправления R01–R07 и причины

| Требование | Реализация |
| --- | --- |
| R01 | Единственный CSS-параметр `--dossier-portrait-size`: expanded 144, compact 120, mobile 104 px. Shared avatar принимает CSS-размер; убраны размеры 88/72 и конкурирующие `!important`. Внешние списки/телефон/родословная сохраняют свои размеры. |
| R02 | Отдельный hit target 44×44; видимая окружность 30×30, Pencil 16×16. Карандаш вынесен к внешнему нижнему углу, не закрывает инициалы; оригинал и редактор имеют разные кнопки и клавиатурный фокус. |
| R03 | Пять семантических токенов: синий, фиолетовый, розовый, зелёный, янтарный. Значения адаптированы к тёмному и светлому скинам; выбранная вкладка отмечена независимо от цвета иконки. |
| R04 | Общие локальные SVG: мужской силуэт на синем, женский с выраженным хвостом на розовом, нейтральный на сером. Вход — только разрешённый `silhouette`. Цветной класс отсутствует на реальном изображении. Ошибка привязана к save/character/asset, поэтому поздний onError не скрывает чужой новый портрет. |
| R05 | `remote.projection()` добавляет `sender` только сообщениям, по каноническому `sender_id`, через существующую owner-specific проверку контактов. `subject` остаётся собеседником. Раньше сообщение использовало `subject`, поэтому «Ты» получал портрет адресата. Теперь только пузырь сообщения использует `sender`; звонки, журнал, контакты, заголовок и участники не изменены. |
| R06 | Прежний двухколоночный Grid синхронизировал высоту строк и оставлял отверстия под короткими карточками. Теперь две независимые вертикальные группы с gap 12 px: текущее/физическое состояние и описательные/социальные сведения. На mobile тот же DOM идёт одной колонкой; resize не перемонтирует редакторы. Прочие вкладки используют последовательный поток, wide-секции доступны полностью. |
| R07 | Публичные даты рождения и родословные #120 сохранены. Условия, Knowledge, личность контакта и чужая переписка не расширяют доступ. Нет изменений SQLite/schema, WorldState, истории сообщений, Narrative/Tabletop-механик, портретных endpoints и вызовов модели. |

Изменённые production-файлы: `backend/runtime_v3/remote.py`, `frontend/src/Phone.tsx`, `Portrait.tsx`, `CharacterDossier.tsx`, `styles/portraits.css`, `styles/dossier.css`. Остальные изменения — QA checkpoint, тестовый сервер, новые проверки и доказательства. Старые материалы `issue83-evidence` сохранены.

Старые сохранения не требуют миграции: новая проекция вычисляется при чтении старого канонического события. Не переписываются отправитель, recipients, delivery/read, history head, время, выбранный вариант. Неизвестному отправителю возвращаются пустой id, нейтральный силуэт и `portrait:null`; публичный справочник не используется для восстановления скрытой личности. Одинаковое имя не объединяет персонажей.

## Воспроизведение и результаты

Команды запускаются из корня репозитория, frontend-команды — из `frontend`.

```sh
python -m pytest -q tests/test_phone_sender.py tests/test_remote_communication.py tests/test_remote_decision_contract.py tests/test_portraits.py tests/test_character_dossier.py tests/test_public_family_directory.py tests/test_narrative_test_world.py tests/test_tabletop*.py
npm run build
DOSSIER_EVIDENCE=../docs/manual_qa/narrative_v4/pr121-polish-evidence/regression PLAYWRIGHT_EXECUTABLE_PATH=/root/.cache/ms-playwright/chromium_headless_shell-1193/chrome-linux/headless_shell npm run test:e2e -- portrait-polish dossier phone
PLAYWRIGHT_EXECUTABLE_PATH=/root/.cache/ms-playwright/chromium_headless_shell-1193/chrome-linux/headless_shell npm run test:e2e -- portrait-polish tabletop
```

- Backend: **422 passed** (37.39 s), финальный прогон выше.
- TypeScript + production build: успешно; существующее предупреждение chunk >500 kB.
- `portrait-polish dossier phone`: **50 passed, 8 skipped** (4.2 min); пропуски — повторная viewport-матрица, уже выполненная desktop-проектом.
- `portrait-polish tabletop`: **21 passed, 4 skipped, 1 failed**; единственный сбой был в новом тесте смены владельца на mobile: использовался отсутствующий desktop-селектор.
- Исправление теста использует существующий mobile actor picker. Промежуточный повтор выявил уточнение имени главного героя с суффиксом `(ГГ)`; после исправления `npm run test:e2e -- portrait-polish --grep 'temporary phone owner'`: **2 passed** (11.3 s), desktop/mobile. Production-код из-за этого не менялся.
- Смоук и телефонные регрессии прошли в серии из 50 сценариев; Tabletop — все 10 сценариев в финальной серии. Числа серий пересекаются и не суммируются как уникальные тесты.

Before получен из отдельного checkout `0ef0aa0`: production frontend/backend без исправлений, туда скопированы только тот же QA checkpoint, тестовый сервер и capture-сценарий; запуск `PR121_BEFORE=1 ... npm run test:e2e -- portrait-polish --project=desktop`. Результат: 4 passed, 2 skipped (after-only). Для пар использованы одинаковые данные, скины, viewport и положение прокрутки. After снят с исправленной сборки.

[Снимки до/после, размеры, видео и логи](pr121-polish-evidence/README.md).

Ограничения: Chromium desktop и эмуляция mobile/Pixel 7, не физический Android; локальный детерминированный провайдер, не живая LLM; синтетические явно различимые изображения и QA save, не пользовательское сохранение. Предупреждение Vite о большом основном chunk осталось; semantic retrieval в тестовой среде использует существующий structural fallback. Полная переработка телефона и другие задачи эпика не выполнялись. В группе телефон сохраняет прежнюю прокручиваемую небольшую область сообщений; отдельные снимки каждого автора показывают её содержимое без изменения геометрии продукта.
