# #38 — жизненное состояние, социальные связи, родословная

Все проверки используют обычный Narrative Runtime и существующий загрузчик #78.
Без платного LLM полный deterministic прогон: `python -m pytest tests/test_life_social.py -q`.
Сценарии событий, проверка agency/Knowledge и вариантов там выполняются с фиксированной
подменой ответа провайдера. В ручной игре LLM может не предложить нужную extraction:
проверяйте canonical результат/диагностику, а не только красивую прозу.

## Старт / reset

```bash
RPG_DEV_TOOLS=1 python scripts/narrative_test_world.py --db /tmp/narrative-family.sqlite3 --checkpoint family
RPG_DB_PATH=/tmp/narrative-family.sqlite3 python -m uvicorn backend.main:app --host 127.0.0.1 --port 8010
```

Каждый reset создаёт новое прохождение, старые сохранения не перезаписывает.
Открыть возвращённый `save`. Начать игру → обычный ход → перезагрузить страницу →
ещё один обычный ход. Мир → «Семья и социальные связи», а также карточки персонажей.
`GET /api/saves/{save}/genealogy` должен давать тот же известный граф без изменения revision.

`family`: Кирилл/Вера супруги, оба родители Аси; Нина/Павел — родители Кирилла;
Тимур — друг Кирилла. Елена — родитель Зои, но Кирилл этого не знает. У Олега
ограничение действий из-за травмы руки. Время/даты заданы исходным миром.

## Опека → усыновление (NPC-событие)

Загрузить `--checkpoint family-care`. Биологические родители Аси по-прежнему
Кирилл/Вера; Елена — опекун (`qa_guardianship`). Об этом знают Вера и Елена,
Кирилл ещё не знает. Место жительства, имя и личность Аси не изменены.

1. В родословной Кирилла нет опеки. Переключить управление на Веру штатным выбором
   персонажа: опека видна отдельным типом, не как родительство.
2. Установить завершённое, допустимое в сеттинге усыновление NPC Еленой. Для
   гарантированного без-LLM результата используйте автоматический сценарий
   `test_adoption_guardian_foster_step_and_revocation_preserve_biology_and_personality`.
3. Новый `adoptive_parent`; если опека завершилась — отдельно закрытый guardian.
   Сохраняются биологические edges, IDs, характер, память, Knowledge и место проживания.
4. До отдельного информационного события Кирилл не узнаёт усыновление. Нет автоматической
   смены фамилии или раскрытия биологического происхождения.
5. Отдельное прекращение статуса закрывает выбранный ID, не удаляет предыдущий период
   и не меняет второго опекуна/приёмного родителя. Приёмная семья/отчим остаются отдельными типами.

## Недееспособность и условия

Загрузить `--checkpoint family-incapacitated`. Кирилл жив и остаётся под управлением,
но одновременно действуют `qa_unconscious` и `qa_leg`.

1. Начать игру: обычных choices нет; отправка действия недоступна. API также отклоняет
   действие до LLM. Time Skip с пустым вводом/наблюдение мира доступны.
2. Установить только завершение `qa_unconscious`: сознание/действия восстанавливаются,
   `qa_leg` продолжает запрещать самостоятельное движение.
3. Смена сцены, сутки, неизвестный исход, partial effects и общая фраза о хорошем
   настроении не снимают ограничение. Его снимает только подтверждённое разрешение/отмена.
4. Инфант не может самостоятельно говорить/работать/пользоваться телефоном. Неизвестная
   стадия не даёт взрослой eligibility; этап не создаёт биографию, друзей или профессию.

## Сохранения и ветки — после каждого существенного перехода

- reload сохраняет текущие связи/имя/ограничения и тот же authorized граф;
- regenerate использует исходный before/context: альтернативный ответ не наследует
  развод/смерть/усыновление из заменяемого результата;
- выбор прежнего варианта восстанавливает его состояние, rollback — исходное;
- соседняя ветка сохраняет собственные Knowledge, условия, имена и родословную;
- malformed optional transition даёт warning, но валидный обычный ход сохраняется;
- цикл родительства/опеки, self-edge и несуществующие endpoints отклонены локально;
- старый мир без новых полей проходит import → start → turn → save/reload → turn;
- Tabletop smoke и весь общий backend/E2E набор остаются зелёными.

Детерминированные проверки: `tests/test_life_social.py`; браузер desktop/mobile:
`frontend/e2e/family.spec.ts`. Полный контракт: `docs/canonical-life-social.md`.
