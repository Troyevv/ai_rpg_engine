# #76 — Знания, устаревшие убеждения и исправления

## Подготовка и сброс

```bash
RPG_DEV_TOOLS=1 python scripts/narrative_test_world.py --checkpoint knowledge
```

Использовать выведенное сохранение в изолированной dev-БД/сервере из
[общей инструкции](README.md). Повторный запуск создаёт новое сохранение; реальные
игры не удаляются. Checkpoint уже начат детерминированно, без LLM. `base` и прежние
checkpoints не меняются. Идентификаторы и исходное состояние воспроизводимы.

| Объект | Исходное состояние |
|---|---|
| `qa_oleg_job` | Олег работает в `qa_academy`, fact `qa_oleg_academy` |
| `qa_kirill:qa_oleg_workshop` | known: Олег работает в Мастерской карт |
| `qa_vera:qa_oleg_workshop` | known, то же старое убеждение |
| `qa_timur:qa_oleg_workshop` | known, то же старое убеждение |
| `qa_oleg:qa_oleg_academy` | known: актуальная работа самого Олега |

Обе записи Fact имеют subject `qa_oleg`, predicate `primary_employment`, scope `""`,
но разные value. Исходные знания — явно заданная предыстория fixture, без выдуманного
исторического события. Кирилл, Вера и Тимур дома; присутствие само по себе не даёт
доступа к сообщению на чужом телефоне.

## Действия и ожидания

1. Спросить Веру, где работает Олег. До подтверждённого сообщения она исходит из
   Мастерской карт, не из GM-only роли в Академии. Проверить Diagnostics: в её
   Knowledge нет нового факта; в World State роль в Академии уже есть.
2. Сохранить/перезагрузить и сделать обычный ход без разговора об Олеге. Старое
   known сохраняется. Само течение времени, даже большой Time Skip без получения
   информации, ничего не удаляет и не исправляет.
3. Организовать получение личного сообщения Олега Кириллу: «Теперь я работаю в
   Академии двух берегов, из Мастерской карт я ушёл». Прочитать сообщение, не
   пересказывать его Вере/Тимуру. Проверить завершённое повествование, Extraction
   и принятый Event: Кирилл — witness, новый факт — fact_id, medium — message.
   Только после этого `qa_kirill:qa_oleg_academy` становится known, старая запись
   — superseded с replaced_by и source_event_id. Вера/Тимур всё ещё верят в Мастерскую.
4. Открыть «Мир → Персонажи → Кирилл → Знания и подозрения»: текущая работа в
   Академии; в «Прежние убеждения» старая работа, отметка «Исправлено», основание
   и новое убеждение. Аналогично проверить «Память». UI не должен показывать
   superseded как подозрение или текущее знание.
5. Сохранить, перезагрузить, сделать следующий ход: исправление сохраняется.
   В контекст Narrative не попадает вся цепочка старых версий; Кирилл действует
   из нового знания, Вера из старого.
6. Перегенерировать исправляющий ход вариантом, где сообщение не прочитано:
   восстановлено прежнее known. Выбрать исходный вариант — восстановлено исправление.
   Rollback возвращает точное исходное знание и историю его ветки. В альтернативной
   ветке без сообщения не появляется история исправления из соседней ветки.
7. На отдельном сбросе проверить слух: suspected об Академии не стирает known
   о Мастерской. Подтверждённое сообщение затем исправляет именно известный старый
   слот. Явное опровержение/признание устаревания без замены даёт refuted/outdated.
   Без такого события статус не меняется.
8. Два противоречащих сообщения в одном ходе: Extraction должен задать Event.order.
   При отсутствии однозначного порядка Resolver выдаёт knowledge_order_ambiguous,
   не выбирает победителя по случайному порядку массива.

## Автоматизированные аналоги и ограничения

`tests/test_knowledge_lifecycle.py` проверяет grounded correction, все статусы,
противоречия, подозрения, невалидные источники/ревизии, фон, 120 NPC, legacy migration,
обычный start → turn → save → reload → next turn, regenerate/rollback и независимые
ветки. Hypothesis проверяет один текущий known value в слоте при цепочках исправлений.
`frontend/e2e/knowledge.spec.ts` проверяет UI, источники, reload и отсутствие рассылки
на desktop/mobile через обычное выполнение игрового job.

Детерминированные тесты не платят за LLM. Ручной live QA нужен для качества семантического
извлечения. Не считать запись намерения «хочу получить сообщение» подтверждением
его получения. Неструктурированные старые утверждения исправляются только явно через
supersedes + событие с обоими fact_id; эвристического анализа всей истории нет.
