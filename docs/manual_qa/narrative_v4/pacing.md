# #68 — интенсивность, риск и исходы истории

Используется тот же QA-мир #78, checkpoint `pacing`: семейный контекст,
проживание/роли и принятые Milestones. Это не отдельная кампания.

```bash
RPG_DEV_TOOLS=1 python scripts/narrative_test_world.py --checkpoint pacing
```

Загрузка и отдельная dev-БД описаны в [README](README.md). Каждый запуск создаёт
новое прохождение; для сравнения профилей используйте одинаковый старт.

## Матрица

1. Выберите по очереди calm, moderate, dynamic, intense; затем custom. Сравните
   Director → narrative_policy и диагностику контекста при одинаковом состоянии.
   Dynamic/intense допускают больше релевантных предложений, но не требуют события.
2. Проведите спокойные разговоры: выбранный кандидат не должен сам создавать
   NPC/Thread, портить отношения или менять характер. После принятого развития
   проверьте pressure/quiet, повторный источник и лимит активных линий.
3. Проверьте life_opportunity, existing_thread, external_disruption отдельно.
   Недавний переезд/роль/Milestone может дать возможность обычного следующего хода;
   сам переход не создаёт «жизнь в новом городе». Старый источник теряет влияние.
4. По очереди safe, realistic, harsh, unrestricted и custom. Разрешение тяжёлого
   исхода не гарантирует его появления. В custom переключатели болезни, травмы,
   постоянной травмы, потерь и двух видов смерти независимы.
5. При разрешённом, причинно обоснованном несчастье проверяйте Condition,
   capabilities, Event/Milestone, а не только художественный текст. Запрещённый
   или не прошедший canonical resolver исход оставляет ход ошибочным без записи
   состояния. Проверьте также несовместимую комбинацию нескольких последствий.
6. Смерть NPC/ГГ: при разрешённой смерти ГГ действует штатный #42 выбор преемника.
   Временное управление NPC не меняет категорию current-protagonist death.
   Потеря способности действовать без смерти не требует преемника; варианты
   действий и поведение уважают capabilities.
7. Возможность помощи не означает согласие EXTERNAL, увольнение, переезд или
   разрыв по его инициативе. Проверяйте, что предложение остаётся выбором игрока.
8. natural / prefer_happy / guaranteed_happy_path: сравните связанную с ГГ линию
   и независимую линию NPC. Гарантия сохраняет конкретную достижимую возможность;
   не закрывает конфликт автоматически, не раскрывает тайну и не принуждает к
   романтике. Явный отрицательный выбор игрока не исправляется принудительно.
9. Измените все три настройки между ходами. Существующие Condition, отношения,
   роли, события и тексты не меняются. Перезагрузка сохраняет настройки.
   Regenerate использует первоначальный контекст; выбор старого варианта,
   rollback и новая ветка восстанавливают соответствующие snapshots.
10. На обычном ходе без фонового развития: ровно Narrative + Extraction,
    дополнительных обязательных запросов политики нет. При ошибке risk повторный
    запрос «скрыть последствие» не выполняется. Бюджет не зависит от числа дней.

## Автоматические проверки и границы

`tests/test_narrative_pacing.py` покрывает матрицу пресетов, независимые custom
поля, давление/затишье/лимиты, причинные исходы, EXTERNAL, #42, счастливый путь,
миграцию и lineage. `frontend/e2e/narrative-pacing.spec.ts` проверяет настройки на
desktop/mobile. Существующие reproduction, milestones, protagonist и ordinary
Narrative тесты проверяют интеграцию; полный suite включает Tabletop.

Автоматические прогоны используют подмену провайдера. Художественную
правдоподобность, правильность semantic-классификации произвольного текста и
качество ответов реального провайдера оценивают по этому ручному протоколу.
Сохраняйте preset/custom значения, snapshot, candidate ID, source Event,
diagnostics/usage и фактический текст для воспроизводимости.

## #44 — выразительность NPC (на том же checkpoint)

1. Загрузите `pacing` указанной выше командой. В «Политике истории» выберите
   «Гиперболизированная / аниме» и сохраните. Число ходов, canonical личность,
   Knowledge, отношения и цели не меняются; меняется только
   `world_state.meta.npc_expressiveness`.
2. Перезагрузите страницу: выбранный режим сохранён. В диагностике следующего
   Narrative-контекста появляется инструкция о подаче эмоций/реплик; она не
   разрешает менять личность или согласие NPC и не принимает решения за ГГ.
3. Проведите обычный ход, сохраните/загрузите, затем сделайте следующий ход.
   Сравните режимы на новых прохождениях одного checkpoint. Уровень риска и
   интенсивность не должны автоматически меняться вместе с выразительностью.
4. Перегенерируйте записанный ход после смены настройки: используется исходный
   контекст хода. Откат и ветка сохраняют значение своего snapshot. Старый save
   без поля загружается с консервативным `realistic`; новая генерация явно
   выбирает `expressive`, если пользователь не указал другое.

Автоматические проверки: `tests/test_world_creation_settings.py`, существующие
тесты политики/lineage и `frontend/e2e/narrative-pacing.spec.ts` (desktop/mobile).
Это протокол ручной проверки, не утверждение о качестве реальной модели.
