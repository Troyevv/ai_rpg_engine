# #255 — разбор после прерванной игровой сессии

Сначала записан [дневник игрока](playtest255-diary.md), затем прочитаны внутренние
данные. Во время игры использовался production UI через Chromium/Playwright:
свободный ввод, кнопка отправки, одна кнопка Retry. Прямых API-запросов для
игровых действий, подмен ответов, новых миров, правок состояния и продукта не было.
HEAD: `47889f9c06e79595fc0e225209e8f2b0c5cfc2b8`, Flash, thinking off, Extraction/6.

## Что действительно произошло

Четыре новых хода (41–44) прошли первый Extraction и сохранились **без repair**.
Пятый Narrative завершился, но поток Extraction прервался после 2206 символов,
внутри строкового значения Fact, без завершённого JSON и usage receipt.
Reservation **665**: provider stream содержит request, 679 текстовых chunks и
`end: complete=false, usage=null`. Это не ответ, отвергнутый Runtime по смыслу,
не доказательство исчерпания max_tokens и не подтверждённый дефект schema transport.

Игрок нажал Retry один раз. Existing Budget обнаружил неизвестный результат
оплаченного запроса и остановил dispatch с сообщением
`Unknown paid outcome; stop before another dispatch`. В журнале приложения есть
ещё одна неудачная попытка Extraction, но нового provider reservation нет:
**ручной Retry не отправил второй запрос модели**. Сессия прекращена, исходная
предварительная проза не заменена и не отменена.

Точная первоначальная причина обрыва — соединение, provider event, адаптер либо
иная ошибка — по сохранённым данным не установлена. Журнал запросов сохраняет
частичный текст, но не первоначальное исключение; поле job.error после Retry
содержит уже ошибку Budget. Raw QA stream также не сохраняет исключение/terminal
provider envelope. Поэтому нельзя приписывать остановку конкретному дефекту
DeepSeek или Runtime. Нехватка диагностической истории — ограничение расследования.

Блокировка повторного запроса вызвана учётом QA, а не отказом компилятора игры.
Это не основание объявить Extraction/6 непригодным по результату этого прогона.
При этом пользовательский опыт действительно прервался, и полноценная игровая
приёмка **BLOCKED**, а не PASS.

## Сохранность и отдельные виды активности

Исходник — `work/issue255-recovery-live/final.sqlite`; SHA256 не изменился.
Одна рабочая копия, один сервер, последовательные действия. Revision **45 → 49**,
четыре принятых хода и прежние variants сохранены. Последняя принятая сцена остаётся
в `loc_home_galina`. После остановки платного сервера запуск с запрещённым provider
IO и открытие UI подтвердили полное равенство снимка после cold reload.
Пятый job и его Narrative доступны для дальнейшего штатного восстановления.

- 5 обычных вводов; 4 сохранения; 1 несохранённый ход; 1 ручной Retry без dispatch.
- 0 автоматических repair; 4 из 4 завершённых Extraction приняты с первого ответа.
  Прерванный пятый не засчитывается как успешный первый ответ.
- Телефонных действий игрока: 0. Один штатный remote initiative вызов прислал
  сообщение Галины; счётчик unread вырос на один. Это не дополнительный Narrative-ход.
- Вызовов фоновых сцен / новых background History в этой сессии: 0.
- Переходы между самостоятельными локациями, LTA и длительные последствия не
  проверены: сессия оборвалась раньше. В квартире произошёл лишь переход на кухню.

## Расходы

Разрешено до **220 новых вызовов / $2.50**. Existing Budget/ledger получил только
новые разрешённые cumulative значения: 669 calls / $5.8837474 от phase baseline 205.
Новых таблиц авторизации и систем бюджетирования не добавляли.

Фактически 11 provider attempts, reservations 655–665: **10 settled + 1 unknown**.
Подтверждённые usage: **197 297 input / 8 384 output tokens**, **$0.0692499**
по консервативным тарифам $0.30/M input + $1.20/M output. Для неизвестного вызова
сохранён полный штатный резерв **$0.3244032** (1,048,576 input + 8,192 output).
Итого учтено **$0.3936531**. Размер резерва не выдан за реальные токены или списание.
Остановка произошла из-за неизвестного результата, не исчерпания $2.50/220.

   Частичный текст не даёт оснований вычислять точный расход.

   минимальное сохранение ошибки каждого attempt в существующей диагностике.
   Это предложение следующей работы, не выполненная здесь правка продукта.
3. После разрешения вопроса с неизвестным расходом штатно восстановить тот же
   Narrative и возобновить естественную сессию. Не подбирать другой сюжет ради PASS.
