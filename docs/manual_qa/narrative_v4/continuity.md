# #71 — Непрерывность, повторы и сжатие рутины

## Подготовка / сброс

```bash
RPG_DEV_TOOLS=1 python scripts/narrative_test_world.py --checkpoint continuity --db data/dev-continuity.sqlite3
RPG_DB_PATH="$PWD/data/dev-continuity.sqlite3" python -m uvicorn backend.main:app --host 127.0.0.1 --port 8010
```

Повтор загрузчика создаёт новое прохождение; текущие данные не удаляет. Выберите
полученные world/save в UI. Используется мир #78 с прежними canonical IDs: qa_kirill
здесь Илья, qa_vera — Соня, место встречи — «Гвоздь». Base не изменён. Намеренно
устаревшие ситуация Сони и состояние qa_meeting описывают дорогу/ожидание встречи.
Скрытое письмо Олега остаётся скрытым. Автоматические тесты используют фиктивного
провайдера; ручная игра проверяет отдельно качество ответа выбранной модели.

## Проверки

1. Начать игру, подтвердить договорённость, встретиться, поговорить, попрощаться
   и разойтись. После принятого started/advanced/ended Event старые «идёт / ждёт»
   исчезают из текущих situation/state. Если нового описания нет, значение пустое,
   а не выдуманный маршрут. qa_meeting остаётся developing. Завершённое намерение
   #75 и выполненный план #66 не становятся новыми предложениями встречи.
2. Следующий ход: «Осматриваюсь». Не организуется та же встреча. Сохранить,
   перезагрузить, сделать ход. Regenerate использует исходный Director.continuity;
   выбор прежнего варианта восстанавливает его состояние. Откат и другое действие
   создают ветку без событий отвергнутого варианта.
3. Несколько спокойных ходов в той же сцене: continuity.pressure может повысить
   приоритет уже обоснованного развития, но события/катастрофы не обязательны.
   Изменение Knowledge, плана или значимое решение сбрасывает застой постепенно.
4. Ответить на вопрос / отвергнуть предложение. Receipt в History имеет canonical
   basis_ids, status и Event provenance. Повторный вопрос с тем же основанием не
   появляется как новая возможность. Разные формулировки одного варианта дают один
   выбор; пользователь всё ещё может написать собственное действие.
5. Закрыть отдельную линию и проверить, что она не открывается без нового принятого
   Event. Завершение встречи само по себе не закрывает линию отношений.
6. Воспользоваться milestone checkpoint: последствия переезда/новой работы доступны
   без нового Thread; релевантность ослабевает с временем и дальнейшими сценами.
   Отвергнутая возможность с неизменным основанием не возвращается. NPC без знания
   факта не реагирует на него; совместный опыт не передаётся посторонним.
7. «Жду у окна», рутинная дорога/работа: допустимо краткое описание не более 30 минут.
   Проверить canonical world_time и календарь. Ближайшая договорённость, конец
   интервала или прерывание ограничивает ход. При открытом вопросе NPC нет молчаливого
   согласия и пропуска ответа игрока. Detailed Time Skip проверить отдельно.
8. Убедиться в работе обычного Narrative и отсутствии изменений Tabletop. На desktop
   и mobile встреча → уход → reload → следующий ход сохраняют сцену и вёрстку.

Автоматическое покрытие: tests/test_narrative_continuity.py, обновлённые проверки
choices, frontend/e2e/narrative-continuity.spec.ts. Дополнительно полный Python suite,
frontend build и полный Playwright suite. Проверки включают 120 дополнительных NPC,
20 000 исторических событий, архивный receipt за 250 пакетами и Knowledge/agency.
