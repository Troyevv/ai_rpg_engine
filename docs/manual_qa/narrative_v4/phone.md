# #70 — Связь и телефон

## Подготовка

```bash
RPG_DEV_TOOLS=1 python scripts/narrative_test_world.py --checkpoint phone --db data/dev-phone.sqlite3
RPG_DB_PATH="$PWD/data/dev-phone.sqlite3" python -m uvicorn backend.main:app --host 127.0.0.1 --port 8010
```

Повтор загрузчика создаёт новое прохождение. Base и предыдущие checkpoints не
изменены. QA использует вымышленные адреса `qa-*`, включая службы; реальные звонки
не выполняются. Для автоматических проверок используются детерминированные ответы.

## Проверки

1. Открыть телефон у Кирилла. Видны Вера, мастерская и unresolved-знакомый; остальные
   NPC мира не добавлены. «Вера работа» не меняет имя Character. Переключить управление
   на Веру: доступны только её контакты и собственные события.
2. Написать точный текст с кавычками/переносом строки. После отправки текст совпадает
   побайтно; вариантов ответа в чате нет. Открытие телефона не вызывает LLM.
3. Доставить входящий текст через typed NPC proposal. До открытия содержимое не
   видно в UI/Narrative/Knowledge. Открыть: ровно одно приобретение знания с provenance.
4. Открыть импортированную группу. Создать вторую явно. Добавить/удалить участника
   кнопками «Добавить / Удалить / Выйти»: старые сообщения не доставляются вступившему
   позже, будущие не доставляются вышедшему; уже прочитанное знание не исчезает.
5. Входящий звонок на фоне обычных Narrative choices остаётся ringing. Ответить,
   отклонить или игнорировать через телефон. Обычные действия не отвечают за игрока.
6. Ответить и переключать «Разговор по телефону / Физическая сцена». Локации и состав
   камеры не меняются, удалённый собеседник не касается героя и не видит комнату.
   Завершить звонок: вернуть фокус физической сцены.
7. Позвонить самостоятельно. Ответ не предполагается заранее. Подождать canonical
   timeout: пропущенный вызов без выдуманной причины. Проверить журнал вызовов.
8. Позвонить unresolved-знакомому/мастерской. До meaningful endpoint response карточки
   не создаются. Установленная личность связывается по адресу; организация не становится
   одним NPC. Службы без настройки региона не получают вымышленные номера.
9. Сохранить, перезагрузить, сделать следующий ход. Regenerate, выбор исходного
   варианта, rollback и новая ветка сохраняют правильные сообщения/канал без дублей.
10. Изменить портрет Веры в карточке: контакт, переписка и звонок используют тот же
    актуальный портрет/кроп. Unresolved-контакт не запрашивает чужой asset URL.
11. Проверить desktop/mobile, клавиатуру, закрытие модального окна и смену скина.
12. Отдельно проверить согласование встречи в сообщениях через #66: одного предложения
    недостаточно для согласия героя; проверять календарь и provenance, а не только прозу.

Автоматические сценарии: `tests/test_remote_communication.py`, `frontend/e2e/phone.spec.ts`.

## #109 — Потеря возможности продолжать разговор

Использовать тот же `phone` checkpoint и команды подготовки выше; повтор loader
создаёт отдельный reset. Детерминированный автоматический сценарий:

```bash
python -m pytest tests/test_remote_incapacitation.py -q
```

1. Начать игру, выполнить обычный ход. Кирилл звонит Вере; временно взять управление
   Верой, ответить, вернуть управление Кириллу и фокус разговора. До перехода:
   `answered`, один canonical call ID, разные физические локации.
2. Принять через обычный engine job явное утверждение «Кирилл потерял сознание.»
   и `condition_changes` с ID `audit-unconscious`, `effects.conscious=false`,
   `assertion=established` и evidence/player_evidence этого утверждения.
   Автотест подставляет контролируемые Narrative/Extraction ответы; платный LLM
   не требуется и частота такого ответа живой модели не оценивается.
3. После commit/reload: condition активна, `can_act/can_speak/can_perceive=false`;
   тот же звонок `ended`, `provenance=system:participant_incapacitated`.
   History содержит один `remote_transition` с `before/after` и структурированной
   `termination.reason=participant_incapacitated`, ID участников и недоступными
   способностями. Это системное прекращение, не добровольная команда Кирилла.
4. Фокус закрытого разговора возвращается к физической сцене; protagonist, POV,
   физические локации и Knowledge не меняются. Никакого автоматического лечения,
   перемещения, сообщения собеседнику о диагнозе или выбора нового protagonist.
5. LTA на месяц, `max_llm_calls=0`: время продвигается, condition сохраняется,
   звонок не блокирует переход. Здоровый `answered` звонок на отдельном reset
   по-прежнему блокирует LTA. Другие обычные ограничения LTA остаются в силе.
6. Повторить для Веры, смерти каждой стороны и отдельных ограничений
   `can_act/can_speak/can_perceive`. После смерти Кирилла сохраняется штатный
   protagonist-required flow #42; прекращение звонка не обходит его.
7. Regenerate с тем же переходом не дублирует историю. Альтернативный вариант без
   condition восстанавливает `answered` и call focus; выбор исходного варианта
   возвращает condition + ended. Rollback восстанавливает обе стороны перехода;
   следующий обычный ход снова работает с активным разговором.
8. Отклонённый job, в том числе после вычисления remote transition, не публикует
   condition, ended или History частично. Сохранение/перезагрузка ничего не чинят
   скрыто. Для pre-fix сохранения с incapacitation + answered обработка выполняется
   атомарно в следующем LTA до планирования; rollback возвращает исходный snapshot.
9. Ringing не доказывает доступность адресата: его ограничение не становится
   выдуманной причиной отказа. Неспособный продолжать вызов инициатор прекращает
   попытку системно; обычный timeout адресата остаётся `missed`.
