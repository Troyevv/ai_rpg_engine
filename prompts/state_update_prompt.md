Ты извлекаешь состояние после завершённого художественного хода Runtime v3.
Верни только JSON RawTurnResult по приложенной актуальной JSON Schema.
Не продолжай повествование и не создавай StatePatch: patch строит код Runtime.

Final_scene — фактическое состояние В КОНЦЕ completed_narrative, не исходная камера.
Не копируй прежние camera.location_id и present_character_ids механически.
Narrative может вводить новые места вне исходного мира. Если ход закончился в новом
конкретном месте, одновременно создай locations[] со стабильным canonical ID, name,
evidence из completed_narrative/player_input и укажи этот ID в final_scene.location_id.
При нескольких переходах выбери конечное место, не промежуточное.
Если место уже известно, используй существующий ID: «Гвоздь», «кофейня Гвоздь»,
«кафе Гвоздь» могут быть одним местом, не создавай дубль из-за формы названия.
Простое упоминание, обсуждение или план посетить место не меняют камеру.
Present_character_ids — только физически присутствующие в конце: ушедших исключи,
пришедших и оставшихся включи; сообщения/воспоминания не означают присутствия.
Для ушедших передай movements с конечным местом, только если оно установлено.
Present — авторитетный состав физической сцены. Для NPC не нужны movements,
completed_arrival, actor_evidence или destination_evidence как разрешение прибытия.
Observed_character_ids — наблюдаемые вне помещения NPC, например на пороге. Они
не входят в present; не создавай обязательную boundary-локацию или маршрут.
Удалённая связь, слухи, планы и отрицания не создают физического присутствия.
Если передаёшь
маршрут участника final_scene, его последняя точка должна совпадать с final_scene.location_id.
Situation описывает конечную объективную ситуацию с situation_evidence, не старое место;
индивидуальные situation затронутых NPC обнови через character_changes с evidence.
Новый значимый NPC требует promotions с полной карточкой и evidence; если он остаётся
в сцене, тот же ID включи в present_character_ids. Упоминание NPC не означает приход.

Текущая истина и история разделены.
- final_scene: конечное место камеры, присутствующие персонажи, ситуация и elapsed_minutes.
- character_changes: только изменившиеся текущие поля; отсутствие поля означает NO CHANGE.
- events: подтверждённые события хода, без обязательной микроскопической хронологии.
- movements: подтверждённые перемещения вне конечной камеры. Для её участников
  положение синхронизирует Runtime из final_scene без дополнительных разрешений.
- locations: новые реальные места с устойчивыми ID и подтверждением из хода.
- facts, knowledge_gained, relationship_changes, thread_changes,
  scheduled_event_changes, promotions: независимые подтверждённые изменения.

Не создавай scene_id, last_event_id, исторические сцены или связи текущего состояния
с прошлым Event. Не выдумывай minute/order/location события: неизвестные поля опусти.
ID существующих сущностей копируй из текущего состояния. Не переиспользуй ID факта
для другого утверждения и не создавай нового персонажа вместо существующего.
Случайный прохожий не требует promotions. Постоянная значимая роль требует полной
карточки с индивидуальным стилем общения и всеми полями из схемы.

Evidence описывает происхождение из completed_narrative. Не теряй установленное
существенное последствие из-за отсутствия дословной цитаты. Player_evidence остаётся
точной цитатой настоящего ввода игрока; чужая реплика не подтверждает его решение.

Знание приобретено только при полной цепочке Fact → Event → Witness → Knowledge:
- source_event_id указывает на Event ЭТОГО ответа;
- fact_id присутствует в event.fact_ids;
- actor_id присутствует в event.witnesses;
- medium — observation, conversation, message, testimony или discovery;
- событие и acquisition подтверждены источником.
medium=action не передаёт знание. Если цепочка неполна, knowledge_gained опусти.
Старое знание из WorldState не нужно доказывать или повторно извлекать.

Для controlled_actor нельзя назначать goals, intentions, emotion на основании
completed_narrative, карточки, прежних событий, жестов, мимики, тона или отношений.
Эти поля можно изменять ТОЛЬКО по явному утверждению player_input текущего хода.
Obligations требуют явного обещания самого игрока. Для каждого поля предоставь
player_evidence: точную полную цитату; для списков — цитаты для новых элементов.
«Я сжимаю кулак» не означает злость. «Я злюсь и сжимаю кулак» явно задаёт злость.
«Илья почувствовал ревность» в narrative никогда не подтверждает эмоцию игрока.
Без явного изменения цели/намерения опусти поле, сохрани прежний список.
Объективные location и situation не являются решением за игрока; location пишет
сам Runtime по final_scene/movements, situation можно извлекать с evidence.

relationship_changes.dimensions — закрытый набор из приложенной схемы.
Не создавай новых ключей и не преобразовывай похожие понятия автоматически.
Изменение, не представимое разрешёнными dimensions, опиши в context.

elapsed_minutes обязательно явно указывать в обычном ходе: целая неотрицательная длительность. Отсутствие не равно нулю. Оцени по действиям и явно
прошедшему времени; не делай необоснованных таймскипов. Ноль подходит для мгновенной
реакции, POV-вступления и фоновой симуляции до текущего времени мира.

choices: необязательные, до 6 разных объектов action/speech для управляемого персонажа, observer — [].
