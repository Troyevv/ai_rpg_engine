Extraction/11. Сцена уже произошла. Извлеки изменения из готовой прозы. Если изменений нет, верни {}. Пустые разделы можно опустить.
В scene укажи текущую ситуацию. При точном времени передай end_time, например {"day_offset":0,"time":"19:00"} или {"day_offset":1,"time":"07:00"}. Иначе оцени elapsed_minutes. Обычное прибытие передай один раз через scene.ending: location_id и present_ids только физически присутствующих в конце. Для нового места объяви locations. Для сложного маршрута передай последовательность movement и только дополнительные сведения о составе. Конечное положение участников следует из последней остановки. Упоминания, воспоминания, наблюдение издалека и звонки не меняют физический состав. Уход без известного назначения обозначается departure, выход из комнаты того же дома — local_exit.
Для нового знания передай information с claims. Каждый claim содержит fact.text или существующий fact_id и perceived_by с фактическими получателями. Для услышанного в разговоре достаточно одного claim с получателями. Отдельная запись в facts не передаёт знание слушателю. Различай слова персонажа и объективный факт. Для слуха укажи assertion=rumor и status=suspected. Указывать отдельные Event, Witness, маршрут разговора или цитату игрока для обычных изменений не требуется.
При необходимости используй разделы NPC, отношений, обязательств, имущества, семьи и других последствий из схемы. Сохраняй канонические личности и данные существующей беременности. Время, возраст и объективные процессы рассчитывает Runtime.

Сначала фиксируй долговременные перемены, которые уже произошли. Учитывай каждого участника такого изменения. Различай впечатление от встречи, появление в жизни нового знакомого и изменение устойчивой связи. Сохраняй известное имя нового постоянного участника даже при неполной биографии. Учитывай повторяющийся опыт разными ходами. Планы и предположения оставляй планами.
В development_evidence.actor_id укажи того, чей собственный опыт меняется. Кирилл видит, как Тимур учится слушать ученика: actor_id Тимура, Кирилл может быть в perceived_by. Наблюдение само по себе не устанавливает черту героя. Устойчивые черты и убеждения меняются по накопленным эпизодам. Для известия о смерти или другом жизненном статусе достаточно назвать получателей в perceived_by самой записи.
Для общего постоянного переезда передай всех жильцов в actor_ids одной residence_changes. Посещение меняет только позицию. При замене единственного действующего места жительства или работы укажи replaces="current"; дополнительная работа сохраняет прежнюю. В role_changes, residence_changes и social_relation_changes укажи perceived_by тех, кто узнал о перемене. Обсуждение развода и подача заявления сохраняют действующий брак; только окончательное расторжение — пара и kind="divorce". Для помолвки — engaged, для регистрации брака — spouse. Для открытия фазы ID необязателен.
Подписанный сегодня приказ о переводе с завтрашнего дня — уже известный подписанту факт (information с датой вступления и perceived_by). До этой даты прежняя должность действует. Когда перевод вступил в силу, достаточно новой должности с replaces="current". При отдельном закрытии укажи id прежней фазы и status="closed". Должность описывает объективное состояние. Если описываешь ещё и личное решение героя, его источник — ввод игрока.
Для встречи, о которой в законченной сцене ничего не выяснилось, сохрани прежний статус. Для missed нужно установленное в истории отсутствие участника на встрече.
У повторяющегося опыта одного NPC сохраняй ту же тему (theme). Если в поведении проявляется устойчивая перемена, укажи develops с полем и новой формулировкой. Runtime накопит эпизоды разных ходов и обновит профиль. Предложение и ожидание ответа сами по себе не создают помолвку.
