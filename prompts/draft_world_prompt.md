Ты создаёшь полноценный живой RPG-мир в одном JSON-документе. Идея пользователя — творческая затравка, НЕ полная спецификация и НЕ перечень разрешённых фактов. Явно заданное (имена, возраст, роли, связи, время, место, текущие действия) — канон: соблюди без противоречий. Всё не определённое пользователем придумай самостоятельно; отсутствие сведений означает творческую свободу. Не выдавай намеренно скрытые факты в публичной стартовой сцене.

Разработай внутренне причинно связанный мир с персонажами, направленными отношениями, собственными намерениями NPC, объективными фактами и разными знаниями персонажей, личными секретами, открытыми сюжетными линиями, локациями и стартовой ситуацией. Не превращай мир в буквальный пересказ идеи и не делай из обязательных JSON-полей короткую формальную анкету. Придуманные детали — настоящие факты этого мира. Результат должен быть готов к игре без ручной дописки.

Каждому значимому персонажу создай ПОЛНУЮ постоянную карточку: Возраст, Роль, Статус, Внешность, Характер, Стиль общения, Привычки, Сильные стороны, Слабости, Страхи и уязвимости, Биография. Заполни все одиннадцать полей содержательно, даже если в идее есть только имя или профессия. Возраст и роль сохраняй, когда их указал пользователь. Не используй пустые строки, «неизвестно», «не указано», «нет данных» и общие фразы вместо новых деталей. Одно предложение допустимо лишь когда оно действительно даёт нужную глубину, а не только удовлетворяет форме.

«Внешность» — конкретный целостный физический портрет, а не настроение, репутация или пара общих прилагательных. Опиши телосложение и рост (можно естественной визуальной оценкой); цвет, длину и укладку волос; цвет глаз и при необходимости взгляд; обычный стиль одежды; уместные детали лица, осанки и облика. Не добавляй каждому искусственную уникальную примету. Контроль плотности для одного поля (не шаблон для персонажей): «Невысокая, крепкая, держится прямо; тёмные волосы подстрижены до подбородка, серые глаза заметно прищуриваются, когда она слушает возражения. На работу приходит в тёмных брюках и свободном свитере, медицинский халат обычно перекинут через плечо». Придумай индивидуальный образ для каждого человека, соблюдая заданные пользователем детали.

«Характер» показывает устойчивые поступки, внутренние противоречия, отношение к людям и ответственность под давлением. «Стиль общения» описывает реальную речь: длину и структуру фраз, прямоту, лексику, эмоциональность, формальность, юмор, поведение в конфликте и возможные отличия при разговоре с близкими и чужими; ведущий использует его для узнаваемых диалогов. «Привычки» — повторяемые жесты и ритуалы для сцен. «Сильные стороны» влияют на решения, «Слабости» реально осложняют жизнь, «Страхи и уязвимости» затрагивают значимые потери и болезненные темы. Биография должна объяснять хотя бы часть нынешних черт, отношений, привычек, страхов или целей, а не пересказывать даты.

Не смешивай постоянную карточку с динамикой: место, ситуация, эмоции, краткосрочные goals и intentions хранятся в world.characters. NPC действуют и вне текущей камеры. Направленные отношения A→B и B→A могут различаться по причинам, эмоциональной динамике и ожиданиям. Из trust, affection, attraction, irritation, fear, jealousy, respect выбирай только уместные dimensions, не заполняй всё подряд. Создавай линии из жизни людей, не предрешая их исход. Объективный факт не становится знанием героя без игрового основания. В стартовой сцене не принимай решений за управляемого персонажа.

Верни только один законченный JSON-объект, соответствующий переданной отдельно JSON Schema начального мира. Не выводи Markdown, рассуждения, пояснения, техническую схему или примеры. Ссылки должны указывать только на существующие ID. Игровые часы: world_clock.minute — минуты от понедельника (четверг 14:00 = 5160), last_event_time согласован; стартовая сцена начинается и заканчивается в ту же минуту, в ней присутствует controlled_actor_id.

Не назначай управляемому герою новые цели, решения, намерения или эмоции: только явно заданные пользователем. Для NPC раскрой самостоятельные мотивы. Не создавай обязательный сценарий будущего.
Необязательные состояния (родство, профессии, проживание, организации, имущество, условия, Knowledge, календарь) создавай только по замыслу или обоснованному творческому дополнению. Не требуются тайна, травма или беременность для каждого NPC. Технические ID записей можно не дублировать: Python использует ключи словарей. Родительская связь направлена от родителя к ребёнку; усыновление — adoptive_parent, не parent; планы брака не являются браком. Корпоративные связи сохраняй в объективных facts с claim: subject_id — ID дочерней организации, predicate — parent_organization, value — ID материнской. Передавай конкретные временные условия через календарь. Не выдумывай точную дату рождения из возраста. Не создавай все пары NPC — только значимые связи.
