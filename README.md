# AI RPG Engine

Текстовая ролевая игра с отдельной мастерской сценария и выжимки.
**FastAPI + React + TypeScript**, SQLite, локальные модели LM Studio и DeepSeek API.
Streamlit удалён после переноса и проверки основного сценария в браузере.

## Запуск в Windows

Нужны **Python 3.10+** и **Node.js 22.12+ с npm**. Node нужен для первой сборки
и пересборки после обновления frontend, при самой игре отдельный Node-сервер не работает.

1. Обнови репозиторий и запусти **`start.bat` двойным кликом**.
2. При первом запуске создастся `.venv`, установятся Python/npm-зависимости и
   соберётся React. Это требует интернета. Последующие запуски проверяют хеши
   зависимостей и исходников и пропускают ненужную установку/сборку.
3. Launcher дождётся готовности FastAPI и откроет **http://127.0.0.1:8000**.
4. Для остановки — **`stop.bat`**. Закрытие браузера не останавливает сервер.

Повторный start открывает уже запущенный экземпляр. Занятый другим приложением
порт не освобождается принудительно. Ошибки backend: `.runtime/server.log`.
Если Python Launcher `py` отсутствует, bat использует `python` из PATH.

Для ручного запуска (также Linux/macOS):

```bash
python launcher.py start
python launcher.py stop
```

Сервер раздаёт production build React сам. Vite dev server для обычной игры не нужен.
`RPG_PORT` меняет порт launcher. `RPG_DB_PATH` меняет путь к SQLite. Переменные
нужно задать до запуска. Launcher слушает только loopback.

## Как играть

- **Создать** → новый сценарий → напиши идею. После ответа можно отправлять правки:
  сценарист каждый раз возвращает полный актуальный план. История требований и
  черновики подготовки теперь хранятся в SQLite, отдельно по рабочим областям.
- **Создать выжимку** → **Сохранить выжимку**. Сохранить как новый мир можно только
  завершённый результат. Частичные ответы можно скачать; stop сохраняет черновик.
- **Твои истории** в верхней панели → выбери мир → создай/выбери прохождение.
  Там же можно импортировать готовый Markdown в UTF-8.
- **Начать игру**: ведущий пишет первую сцену, обработчик фиксирует состояние
  и предлагает ровно **6 действий**. Всегда доступно собственное действие/реплика.
- Во время streaming можно писать следующий черновик, читать старые сцены,
  переключать экраны, открыть персонажа или остановить запрос.
- **Повторить обработку состояния** повторяет только JSON-обработчик готового текста.
  **Перегенерировать последний ход** заменяет ответ и состояние только после
  успешной проверки. **Откатить** возвращает снимок до хода. Старые ходы архивируются.

Настройки скрыты за кнопкой с ползунками. В игре — строка времени/места/присутствующих,
режим чтения и ссылки на карточки NPC. Панель мира включает метаданные, локации,
редактор сцены, поиск персонажей, фильтр «рядом», отношения, тайны и сюжетные планы.
Зелёная/красная стрелка отражает подтверждённое изменение в текущем ходе.
Память показывает уже существующий журнал событий, без новых механик обработки.

## Модели

В настройках каждой задачи выбираются **Local / DeepSeek**, ID модели,
temperature и лимит ответа. В игре отдельно задаются бюджет контекста и лимит JSON.

**LM Studio**: запусти Local Server на `http://localhost:1234`, обнови список,
выбери ID в настройках задачи и в блоке загрузки, задай context/batch/Flash/KV,
нажми «Загрузить». Одновременно загружается одна локальная модель. Загрузка,
выгрузка, игра и подготовка используют общий координатор: выгрузка занятой
генерацией модели отклоняется. API-задачи не требуют LM Studio.

**DeepSeek**: введи ключ в поле с паролем либо задай `DEEPSEEK_API_KEY` в окружении
backend. Кнопка обновления показывает доступные модели; начальный ID —
`deepseek-flash`, можно указать другой. Ключ из браузера хранится только в памяти
вкладки и после её перезагрузки вводится заново; в SQLite, URL и ответах API его нет.
Запросы отправляются в DeepSeek и оплачиваются по тарифу провайдера.
Автоматического переключения на другой провайдер при ошибке нет.

Используется streaming Chat Completions без thinking, JSON Output для обработки мира:
https://api-docs.deepseek.com/api/create-chat-completion/
`llm.PROVIDERS` содержит описания OpenAI-compatible адаптеров; новый провайдер
можно добавить здесь и в DTO/UI без изменения игровой логики.

## Сохранения и совместимость

По умолчанию остаётся **`data/rpg.sqlite3`** рядом с проектом. Существующие миры,
прохождения, история, архив и черновики ходов используются напрямую. Не нужно
переимпортировать старые выжимки: JSON старых сейвов не перепарсивается и не
переписывается, включая старые миры с семью персонажами.

Схема обновляется автоматически и идемпотентно: сохраняются исходные таблицы,
добавляются только `preparation_workspaces`, `preparation_jobs`, `client_settings`
и ранее предусмотренные недостающие поля игрового цикла. SQL не удаляет данные.
Текущий импорт по шаблону ожидает восемь карточек, включая ГГ; это правило
существовало в исходной ветке и не меняется миграцией.

Имя мира + одинаковый Markdown не создают дубликат; изменённая выжимка с тем же
именем создаёт новую версию. Прохождения имеют независимые снимки. При отмене,
ошибке LLM или конфликте revision игровое состояние не коммитится частично.
После перезапуска сервера незавершённые запросы помечаются остановленными:
готовое повествование можно обработать повторно, неполный ход — повторить целиком.

История/черновики, существовавшие **только в Session State старого Streamlit**, не
были записаны в БД и автоматически восстановиться не могут. Перед переходом
скачай нужный несохранённый текст из старой версии. Сохранённые миры и сейвы остаются.

## Архитектура

- `backend/api/`: FastAPI, DTO, SSE, обработка ошибок и раздача frontend.
- `backend/services/`: подготовка сценария/выжимки и координация задач.
- `backend/repositories/`: дополнительные SQLite-таблицы подготовки/настроек.
- `engine.py`, `context_builder.py`, `state_updates.py`: независимое ядро игры.
- `storage.py`, `engine_storage.py`, `world_parser.py`: хранение/импорт/транзакции.
- `llm.py`: OpenAI-compatible streaming и управление LM Studio.
- `frontend/src/`: React, TypeScript, Tailwind, shadcn/ui-композиции на Radix,
  Framer Motion и Sonner. UI primitives хранятся в исходниках, установлены вручную;
  registry CLI в среде сборки был недоступен. Стили адаптированы под чтение.
- `docs/MIGRATION.md`: аудит исходной версии, карта паритета, API и этапы.

API-документация: **http://127.0.0.1:8000/docs**. POST создаёт задачу, SSE выдаёт
снимки её черновика и статусы. Переподключение получает свежий snapshot без
дублирования текста. Закрытие SSE не отменяет LLM; stop — отдельная команда.
Состояние принадлежит save_id/workspace_id, а не соединению или UI-сеансу.

Первый этап использует **один backend process**. Несколько окон браузера допустимы;
один сейв защищён от параллельных ходов транзакциями и revision. Несколько серверных
worker-ов потребуют вынесенного координатора задач/локальных моделей.
Для будущего удалённого публичного размещения нужно добавить авторизацию и TLS;
сейчас никаких публичных портов launcher не открывает.

Ветки, новые POV, автономные сцены NPC, варианты ответов, учёт стоимости и новая
система памяти **не добавлены**. Контракты не вводят глобального управляемого
персонажа и допускают новые доменные команды. Нынешние правила ГГ сохранены.

## Разработка и проверки

```bash
python -m pip install -r requirements.txt -r requirements-dev.txt
python -m pytest -q
cd frontend
npm ci
npm run build
npx playwright install chromium
npm run test:e2e
```

Browser-тесты запускают настоящий FastAPI/SQLite и production frontend, но
подменяют только LLM в отдельном `tests/e2e_server.py`. Этот файл никогда не
импортируется production-сервером. Desktop/mobile проверки покрывают полный
сценарий, NPC-ссылки, чтение, перегенерацию/откат, reload и остановку.

Для разработки отдельно: `python -m uvicorn backend.main:app --port 8000`,
в `frontend/` — `npm run dev`. Vite проксирует `/api` на backend.
Поддерживается reduced motion; анимации ограничены появлением новых ответов
и переходами модальных окон. Автопрокрутка не тянет вниз при чтении старой сцены.
