# AI RPG Engine

Локальный генератор сценарных основ для текстовых ролевых игр на базе LLM.

Проект разделяет подготовку игры на два этапа:

1. **Сценарист** — получает краткое описание желаемой игры и формирует полный сценарный план: персонажей, отношения, завязку, локации и открытые сюжетные линии.
2. **Генератор выжимки** — превращает утверждённый сценарный план в подробную структурированную выжимку, которую затем можно использовать как контекст для ролевой LLM.

Интерфейс написан на **Streamlit**, а модели запускаются локально через **LM Studio**.

## Возможности

- выбор локальной модели из LM Studio;
- ручная загрузка и выгрузка модели из памяти;
- настройка размера контекста;
- настройка `Eval Batch Size`;
- включение и выключение Flash Attention;
- перенос KV-cache на GPU;
- отдельные параметры генерации для сценариста и генератора выжимки;
- потоковая генерация текста;
- остановка генерации с сохранением уже полученного результата;
- доработка сценарного плана через последующие сообщения;
- Markdown-отображение результатов;
- сохранение сценарного плана и итоговой выжимки в `.md`;
- возможность начать новую игру без перезапуска приложения.

## Как работает

Общий пайплайн выглядит так:

```text
Описание игры
    ↓
Сценарист / LLM
    ↓
Сценарный план
    ↓
Проверка и правки пользователем
    ↓
Генератор выжимки / LLM
    ↓
Полная Markdown-выжимка для RPG
```

Сценарный план можно несколько раз перерабатывать. При новом запросе текущая версия плана передаётся модели как актуальное состояние, поэтому модель должна изменить только запрошенные части и вернуть полный обновлённый вариант.

После утверждения плана вторая стадия получает:

- сценарный план;
- системный промпт генератора;
- обязательный шаблон выжимки.

На их основе модель формирует итоговый Markdown-документ.

### `app.py`

Основное Streamlit-приложение.

Отвечает за:

- пользовательский интерфейс;
- состояние текущей игры;
- выбор и настройку модели;
- запуск сценариста;
- запуск генератора выжимки;
- потоковый вывод;
- остановку генерации;
- скачивание результатов.

### `llm.py`

Слой работы с LM Studio.

Использует:

- LM Studio REST API для получения списка моделей, загрузки и выгрузки;
- OpenAI-compatible API LM Studio для генерации текста.

По умолчанию приложение ожидает LM Studio по адресу:

```text
http://localhost:1234
```

### `prompts/idea_prompt.md`

Системный промпт сценариста. Определяет правила создания сценарного плана.

### `prompts/summary_prompt.md`

Системный промпт генератора итоговой выжимки.

### `prompts/summary_template.md`

Структура, которой должна следовать итоговая выжимка.

### `prompts/example_summary.md`

Пример готовой выжимки.

## Требования

- Python 3.10+;
- LM Studio;
- локальная LLM, совместимая с Chat Completions API;
- достаточно RAM/VRAM для выбранной модели и размера контекста.

Python-зависимости:

```text
streamlit
openai
requests
```

## Установка

Клонировать репозиторий:

```bash
git clone https://github.com/Troyevv/ai_rpg_engine.git
cd ai_rpg_engine
```

Создать виртуальное окружение:

```bash
python -m venv .venv
```

Активировать его.

Windows:

```bash
.venv\Scripts\activate
```

Linux/macOS:

```bash
source .venv/bin/activate
```

Установить зависимости:

```bash
pip install streamlit openai requests
```

## Настройка LM Studio

1. Установить и запустить LM Studio.
2. Скачать нужную локальную модель.
3. Запустить Local Server.
4. Убедиться, что сервер доступен на:

```text
http://localhost:1234
```

Приложение автоматически получает список моделей через LM Studio API.

## Запуск

```bash
streamlit run app.py
```

После запуска Streamlit выведет локальный адрес веб-интерфейса, обычно:

```text
http://localhost:8501
```

## Работа с приложением

### 1. Выбрать модель

В боковой панели выбрать модель, доступную в LM Studio.

Перед загрузкой можно задать:

- размер контекста: `8192`, `16384` или `32768` токенов;
- `Eval Batch Size`;
- Flash Attention;
- размещение KV-cache на GPU.

После этого нажать **«Загрузить»**.

При загрузке новой модели текущие загруженные модели предварительно выгружаются.

### 2. Создать сценарий

В поле сценариста коротко описать желаемую игру.

Например:

```text
Современность. Главному герою 24 года. Он переезжает в новый город
и заселяется в обычное общежитие. Хочу много бытовых сцен,
живых отношений, юмора и постепенной романтики.
```

Сценарист создаст полный план игры.

После генерации можно написать дополнительное требование, например:

```text
Сделай отношения между соседями менее дружелюбными в начале,
а романтическую линию более медленной.
```

Модель получит существующий сценарный план и должна вернуть его обновлённую полную версию.

### 3. Создать выжимку

После утверждения сценария запускается генератор выжимки.

Он использует сценарный план и `summary_template.md`, после чего создаёт подробный Markdown-документ для дальнейшей RPG-сессии.

### 4. Скачать результат

Из боковой панели можно скачать:

```text
idea.md
summary.md
```

## Параметры генерации

В интерфейсе отдельно настраиваются параметры двух стадий.

Для сценариста:

- `temperature`;
- `max_tokens`.

Для генератора выжимки:

- `temperature`;
- `max_tokens`.

Это позволяет использовать более творческие настройки для разработки идеи и более стабильные настройки для финальной структурированной выжимки.

## Загрузка моделей

`llm.py` использует LM Studio API:

```text
GET  /api/v1/models
POST /api/v1/models/load
POST /api/v1/models/unload
```

При загрузке передаются параметры:

```text
context_length
eval_batch_size
flash_attention
offload_kv_cache_to_gpu
```

Генерация выполняется через OpenAI-compatible endpoint:

```text
/v1/chat/completions
```

с включённым streaming.

## Текущий статус

Проект находится в разработке.

На текущем этапе реализован генератор основы новой RPG-сессии: от короткой пользовательской идеи до подробной структурированной выжимки.

Следующий логичный этап развития — использование полученной выжимки непосредственно игровым движком: управление контекстом, историей сцен, состоянием персонажей и динамическая подача нужных частей контекста LLM во время игры.


## Миры и прохождения (SQLite)

Интерфейс разделён на вкладки **«Генерация выжимки»** и **«Игра»**.
Сценарист, правки сценария, потоковый вывод, остановка и скачивание Markdown
остаются в первой вкладке. Управление моделью находится в боковой панели.

После завершения генерации укажите название мира и нажмите **«Сохранить выжимку»**.
Во вкладке «Игра» также можно загрузить готовый `.md` в UTF-8.
Импорт ожидает структуру `prompts/summary_template.md`: семь персонажей с маркером
`👤`, первый — единственный `(ГГ)`, обязательные поля карточек и все основные разделы.
При ошибке структуры запись не создаётся. Остановленную или оборванную генерацию
можно скачать как черновик; кнопка сохранения мира для неё недоступна.

Разбор выполняется кодом, без дополнительного запроса к модели. Сохраняются исходный
Markdown и отдельные JSON-разделы: карточки, отношения, локации, блоки знаний,
стартовая сцена, жанр и сюжетные заметки. Тексты сохраняют авторские формулировки;
семантическое извлечение отдельных секретов, носителей знаний и сюжетных событий
пока не выполняется. Структурная проверка не гарантирует непротиворечивость сюжета.

Во вкладке «Игра» выберите мир и его версию: появятся стартовая сцена, жанр,
имена персонажей и локации. Полные карточки и тайны находятся в блоке
**«Данные ведущего — спойлеры»**. Кнопка **«Создать прохождение»** создаёт независимую
копию состояния. В списке «Мир / сохранение» можно выбрать ранее созданное прохождение
и посмотреть его состояние. Данные доступны после перезапуска и без LM Studio.

Миры неизменяемы: изменённая выжимка под тем же названием создаёт новую версию;
повторное сохранение идентичного текста возвращает существующий мир. Названия
сравниваются без учёта регистра, включая кириллицу. Новые версии не меняют старые
прохождения. Очистка сценария и выжимки не удаляет сохранённые миры.

База по умолчанию: `data/rpg.sqlite3` рядом с кодом приложения. Можно задать другой
путь переменной окружения `RPG_DB_PATH`. SQLite входит в Python, отдельный сервер
не нужен. Для резервной копии остановите приложение и скопируйте файл базы.
Базы и локальные данные исключены из Git.

Таблицы: `worlds`, `world_parts`, `saves`, `turns`. Таблица ходов подготовлена для
следующего этапа. **Генерация игровых ходов, обновление состояния во время игры
и откат пока не реализованы**: текущая вкладка позволяет сохранять, выбирать
и просматривать миры и стартовые состояния прохождений.

Установка зависимостей: `pip install -r requirements.txt`.
Запуск: `streamlit run app.py`.
Проверки: `pip install pytest` и `python -m pytest -q`.

## Игровой интерфейс: чат и боковые панели

Обновите зависимости перед запуском: `pip install -r requirements.txt`.
Теперь требуется Streamlit 1.63 или новее: используются переключение активных
вкладок на сервере и двусторонний компонент для ссылок на NPC.

- **Слева** во вкладке «Игра» находятся только настройки игры: размер текста,
  выделение имён и отдельные параметры модели ведущего. Список моделей обновляется
  по кнопке, поэтому просмотр мира не зависит от доступности LM Studio.
- **По центру** отображается стартовая сцена и история выбранного прохождения
  в формате чата. Ввод новых ходов пока отключён — ведущий ещё не подключён.
- **Справа** раскрываемая панель «Мир и сохранение»: выбор мира/сейва, импорт,
  создание прохождения, метаданные и разделы «Мир», «Сцена», «Персонажи»,
  «Отношения», «Тайны», «Сюжет». Кнопка над чатом скрывает и открывает панель.

Нажатие на имя персонажа в тексте открывает справа его карточку без перехода
на другую страницу и без сброса сеанса. Поддерживаются полные имена, уникальные
первые имена, прозвища в кавычках «…» и явно указанные `aliases` в состоянии
персонажа. Одинаковые первые имена не связываются автоматически. Склонения и
уменьшительные формы нужно задать в `aliases`; угадывание не выполняется.
Уже существующие Markdown-ссылки и блоки кода сохраняются. Сырой HTML из текста
не исполняется. Кнопки имён доступны с клавиатуры.

Карточки и отношения берутся из текущего состояния выбранного сейва при каждом
обновлении интерфейса. Отношения отображаются из `state.relationships`, а не из
старого текста карточки исходной выжимки. Автоматическое извлечение изменений
отношений из игровых событий остаётся частью следующего этапа — обработки ходов.

Переключение вкладок сохраняет черновик генератора, выбранное прохождение и
отдельные настройки режимов. Существующую SQLite-базу переносить не нужно.

### Строка сцены, чтение и навигация

Над чатом отображаются **Время · Место · Рядом** из текущего сейва.
Имена в строке «Рядом» открывают карточки. Для старых выжимок используются только
явные подписи и однозначное время; упоминание персонажа не считается присутствием.
Недостающие данные отображаются как «Не указано». В правой панели → **Сцена →
Уточнить строку сцены** можно сохранить время, место и присутствующих для текущего
прохождения. Изменяется только `scene_meta` сейва; исходный мир и история остаются
неизменными. Пустой список присутствующих в заданной метаинформации означает «Никого».

**Режим чтения** скрывает обе панели. Выход восстанавливает прежнее состояние
правой панели. Клик по NPC временно открывает карточку даже во время чтения.
Настройки текста над чатом доступны и при скрытой левой панели: размер шрифта,
межстрочный интервал и ширина текста при чтении.

В разделе **Персонажи** доступны поиск по имени/прозвищу, фильтр **Все / Рядом**,
кнопки **Назад / Вперёд** и счётчик карточек. Нажатие на NPC в тексте или строке
сцены сбрасывает мешающий фильтр, чтобы выбранная карточка гарантированно открылась.

Изменения отношений показываются зелёной **↑ Улучшение** или красной
**↓ Ухудшение**, с причиной и номером хода (если он сохранён). Индикатор берётся
только из явного поля отношения, например:

```json
{"change": {"direction": "up", "reason": "Помог в трудный момент", "turn": 4}}
```

Поддерживаются `up` и `down`; без причины или направления стрелка не выводится.
Сам текст отношений не используется для угадывания изменения. Поле будет
заполняться обработчиком игровых ходов; сейчас интерфейс отображает сохранённые данные.
