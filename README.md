# AI RPG Engine

**AI RPG Engine** — локально запускаемый движок AI-RPG с двумя независимыми режимами: **Narrative** (интерактивная история с живым миром) и **Tabletop** (настольная RPG с AI-ведущим и правилами на сервере).

**Стек:** Python, FastAPI, SQLite, React, TypeScript, Vite. Версия приложения, объявленная backend API и frontend package, — **2.0.0**. Проект находится в активной разработке; основное направление — **Narrative Mode**.

> Этот README описывает код ветки `master`, а не ещё не влитые Issues и PR. Название Epic «Narrative Runtime v4» обозначает развитие существующего ядра `backend/runtime_v3/`, **не отдельный переключаемый runtime v4**.

## Режимы

| | Narrative Mode | Tabletop RPG |
|---|---|---|
| Цель | Свободная интерактивная история | Кампания с проверками, ресурсами и боем |
| Роль модели | Повествование и смысловое извлечение событий | Интерпретация намерений и художественное описание |
| Источник состояния | Канонический World State и принятая история событий | Серверный Rules/Dice Engine и Game State |
| Решения игрока | Контроль выбранного персонажа; POV независим | Команды и броски в рамках правил |

Режимы разделяют инфраструктуру LLM, API, SQLite и интерфейса, **но не игровые модели состояния и правила**.

## Narrative Mode

Narrative позволяет описывать действия свободным текстом или выбирать предложенные варианты. Модель развивает историю, а движок сохраняет происходящее как структурированное состояние мира. Это не чат, в котором единственной памятью служит текст предыдущих сообщений.

### Как проходит ход

```text
Действие / реплика игрока
  → Context Builder: релевантная сцена, персонажи, знания, история и правила
  → Narrative LLM: продолжение истории
  → Extraction LLM: смысловое извлечение RawTurnResult
  → StateResolver: проверки структуры, ссылок, agency и инвариантов
  → WorldStateV3 + WorldHistoryV3: принятые изменения
  → атомарное сохранение хода, состояния, варианта и диагностики
```

**Разделение ответственности принципиально:** LLM пишет художественный результат; Extraction интерпретирует его смысл; Python проверяет допустимость изменений канонического состояния. Runtime не пытается устанавливать литературную истину сравнением точных фраз или требовать от модели заранее разрешённого сюжетного результата. Некорректные необязательные изменения могут отклоняться с диагностикой; нарушения критичных инвариантов не должны молча записываться в сохранение.

### Состояние мира и управление

- **Canonical World State:** персонажи, сцены и присутствие, локации, время, знания, отношения, цели, обязательства, события, сюжетные линии и другие структурированные сущности.
- **POV / камера ≠ Controlled Actor:** можно наблюдать за другим персонажем или за миром без главного героя, не передавая управление его решениями модели.
- **Player agency:** LLM не назначает управляемому персонажу добровольные решения, намерения, обязательства и эмоции вместо игрока. Направленные чувства в отношениях могут меняться от подтверждённых взаимодействий по отдельным правилам.
- **Knowledge:** объективная истина мира отделена от того, что конкретный персонаж знает, предполагает или не знает. Секреты не становятся общедоступными из-за появления в тексте.
- **NPC:** собственные характеры, мотивации, ценности, отношения и инициатива; действия могут происходить без прямой команды игрока.
- **Living World:** история, параллельные сцены, последствия событий и контекст персонажей сохраняются между ходами.

### Время, развитие и взаимодействия

- **Календарь:** григорианский или пользовательский профиль, игровая дата/время, праздники и сезонность, запланированные события.
- **Time Skip и Long-term Advance:** короткие пропуски времени и ограниченное событийное продвижение на недели, месяцы или годы. Это не непрерывная поминутная симуляция всех NPC.
- **Жизнь персонажей:** семейные и социальные связи, родство, статусы жизни, возрастные этапы, роли, условия, внешность, владения и развитие личных целей.
- **Отношения:** направленные показатели с контекстом и подтверждаемыми изменениями; объективное родство и семейные связи хранятся отдельно от субъективных чувств.
- **Связь:** контакты, сообщения, групповые беседы и звонки через канонический Remote Runtime в мирах, где такие каналы включены. NPC могут инициировать связь в повествовании; Extraction передаёт событие существующему механизму телефона.
- **Жанр, темп и риск:** настройки помогают направлять стиль и развитие истории, но не заменяют канонические факты или решения персонажей.

### История, варианты и диагностика

- **Streaming** повествования и адаптивный интерфейс для desktop/mobile.
- **Сохранения и версии ходов:** состояния до/после, переключение вариантов, перегенерация с исходным контекстом и откат с сохранением истории изменений.
- **Context Builder:** ограниченный релевантный контекст вместо полного дампа всех карточек и событий мира.
- **Диагностика:** этапы запросов, расход токенов, известная стоимость, ошибки, предупреждения и результаты применения изменений.
- **Карточки персонажей и Inspector:** сведения о персонажах и связях, календарь, журнал и другие представления состояния.
- **Скины:** разные стили оформления, включая Cyberpunk, Medieval, Noir и другие; оформление не создаёт второй игровой runtime.

Подробнее: [Narrative Runtime и скины](docs/NARRATIVE_RUNTIME_SKINS.md), [живой мир](docs/LIVING_WORLD.md), [знания персонажей](docs/knowledge-lifecycle.md), [инициатива NPC](docs/npc-initiative.md), [взаимодействия на расстоянии](docs/remote-communication.md), [Long-term Advance](docs/long-term-advance.md).

## Создание мира Narrative

Основной путь — **идея → генерация структурированного черновика → проверка → редактор → Start Game**.

1. Опишите идею мира и настройте жанр, географию/тип мира, примерное количество NPC, выразительность, темп, риск, календарь и начало игры.
2. Генератор создаёт черновик канонического мира. Результат проходит структурные и смысловые проверки; ошибки и предупреждения отображаются автору.
3. Проверьте и при необходимости измените персонажей, отношения, локации, факты, календарь и другие сущности в мастерской.
4. Подтвердите мир и начните отдельное прохождение. Черновик и история его версий сохраняются.

Также доступны импорт/экспорт канонического JSON и импорт legacy Markdown/TXT. Маршрут «Со Сценаристом» остаётся отдельным вариантом подготовки. Сбои ответа внешней LLM не гарантируют автоматического восстановления без вмешательства автора: качество и стабильность генерации зависят в том числе от провайдера и сложности запроса.

Подробнее: [подготовка мира](docs/WORLD_PREPARATION.md), [настройки жанра](docs/genre-policy.md).

## Tabletop RPG

В `master` доступен отдельный **Tabletop D20 Basic v2**: создание кампании и героя, проверки и кубики, исследование, диалоги, задания, инвентарь, пошаговые столкновения, сохранения и расширение мира через проверяемые операции.

**Правила и броски принадлежат серверу.** LLM может интерпретировать действие, вести диалог и описывать результат, но не подменяет вычисления урона, HP, ресурсов или результаты кубиков.

**Universal Tabletop 2.0** развивается в [PR #33](https://github.com/Troyevv/ai_rpg_engine/pull/33). Пока PR не влит, его новые схемы, редакторы и механики **не считаются возможностями `master`**.

Подробности о текущем Tabletop и ограничениях: [docs/TABLETOP.md](docs/TABLETOP.md).

## Установка и запуск

### Windows — основной способ

Требуются **Python 3.10+** и **Node.js 22.12+ с npm**.

```bat
git clone https://github.com/Troyevv/ai_rpg_engine.git
cd ai_rpg_engine
start.bat
```

`start.bat` запускает `launcher.py`. При первом старте launcher создаёт `.venv`, устанавливает Python-зависимости, выполняет `npm ci` и собирает frontend. Затем запускает FastAPI и открывает:

**http://127.0.0.1:8000**

Остановка: `stop.bat`. Повторный запуск обнаруживает уже работающий экземпляр. Логи сервера: `.runtime/server.log`.

### Запуск через Python

```bash
python launcher.py start
python launcher.py stop
```

Launcher поддерживает `--no-browser`. На других ОС понадобится установленный Python и npm; Windows-скрипты `.bat` к ним не относятся.

### Разработка

Из корня репозитория:

```bash
python -m pip install -r requirements.txt -r requirements-dev.txt
python -m uvicorn backend.main:app --reload --host 127.0.0.1 --port 8000
```

В отдельном терминале:

```bash
cd frontend
npm ci
npm run dev
```

Vite проксирует `/api` на `http://127.0.0.1:8000`. Для обычного запуска собранный frontend раздаётся через FastAPI.

### Подключение моделей

| Провайдер | Настройка |
|---|---|
| **Local / LM Studio** | Запустите локальный OpenAI-compatible server (по умолчанию `http://localhost:1234/v1`) и выберите модель в UI |
| **DeepSeek** | Укажите ключ в настройках приложения или `DEEPSEEK_API_KEY` на сервере |
| **Другой OpenAI-compatible API** | Задайте `COMPATIBLE_BASE_URL` и `COMPATIBLE_API_KEY`, затем выберите провайдер и модель |

Для задач повествования, подготовки мира и генерации доступны отдельные конфигурации моделей. Thinking поддерживается там, где это предусмотрено выбранным провайдером/моделью. Реальный ответ внешнего API может отличаться по качеству и расходам.

**Безопасность:** ключ DeepSeek, сохранённый через UI, шифруется на сервере. Для резервного копирования нужны и SQLite-файл, и расположенный рядом с ним `.credential-key`. Приложение рассчитано на локальное использование/доверенную сеть и **не предоставляет публичную многопользовательскую авторизацию**.

### Основные переменные окружения

| Переменная | Назначение |
|---|---|
| `RPG_DB_PATH` | Путь к SQLite; по умолчанию `data/rpg.sqlite3` |
| `RPG_PORT` | HTTP-порт launcher; по умолчанию `8000` |
| `RPG_HOST` | HTTP-интерфейс; по умолчанию `127.0.0.1` без локального HTTPS |
| `DEEPSEEK_API_KEY` | Резервный способ передать ключ DeepSeek |
| `COMPATIBLE_BASE_URL`, `COMPATIBLE_API_KEY` | Настройки OpenAI-compatible провайдера |
| `RPG_DEV_TOOLS` | Явное разрешение на запуск dev-only утилит |

### Телефон и PWA

Для браузера телефона и установки PWA предусмотрены адаптивный UI и локальный HTTPS. На Windows выполните `setup_https.bat`, затем настройте доверие к локальному CA на телефоне. **Не публикуйте локальный сервер в интернет без отдельной системы защиты.**

Пошаговая инструкция: [docs/MOBILE_PWA.md](docs/MOBILE_PWA.md).

## Структура репозитория

```text
backend/
  api/              HTTP/SSE endpoints, DTO
  services/         подготовка мира, Narrative orchestration, LLM-процессы
  repositories/     SQLite, документы, сохранения и проекции
  runtime_v3/       канонический Narrative World State, Resolver, History
  tabletop/         независимые Tabletop Rules/Dice/Game runtime
frontend/
  src/              React/TypeScript, Narrative, Tabletop, Inspector, скины
  e2e/              Playwright desktop/mobile
tests/              backend и интеграционные проверки
docs/               архитектура, сценарии и технические контракты
scripts/            QA и инструменты разработчика
engine.py           обработка Narrative jobs
context_builder.py  сборка контекста LLM
llm.py              провайдеры и запросы к моделям
storage.py          базовое SQLite-хранилище
launcher.py         bootstrap и управление сервером
```

Текущий канонический Narrative schema version — **3** (`WorldStateV3`). Документация и задачи Epic #36 развивают именно эту систему.

## Тестирование

```bash
python -m pip install -r requirements.txt -r requirements-dev.txt
python -m pytest -q

cd frontend
npm ci
npm run test
npm run build
npx playwright install chromium
npm run test:e2e
```

Playwright настроен на desktop и mobile, а E2E запускает тестовый backend. Проверки с подменённой моделью не доказывают стабильность генерации на реальном DeepSeek или другой внешней LLM.

Для воспроизводимого Narrative QA есть **отдельный dev-мир**, не затрагивающий основную БД:

```bash
RPG_DEV_TOOLS=1 python scripts/narrative_test_world.py
```

В PowerShell переменная задаётся как `$env:RPG_DEV_TOOLS = '1'`, после чего запускается `python scripts/narrative_test_world.py`.

Сценарии и подключение dev-БД: [docs/manual_qa/narrative_v4/README.md](docs/manual_qa/narrative_v4/README.md).

## Статус и ограничения

- **Narrative:** основной активно развиваемый режим. Runtime v3 расширяется задачами [Epic #36](https://github.com/Troyevv/ai_rpg_engine/issues/36); наличие Issue не означает, что её функциональность уже в `master`.
- **Tabletop:** в `master` — D20 Basic v2; Universal Tabletop 2.0 находится в отдельном PR.
- **Симуляция мира:** событийная и ограниченная бюджетом, а не постоянная фоновая симуляция каждого NPC.
- **Варианты ходов:** поддерживаются; полноценные именованные ветки истории не заявлены как готовая функция.
- **Генерация LLM:** возможны ошибки провайдера, неполные ответы и необходимость ручной правки. Автоматические тесты и структурная валидация не заменяют проверки реальных миров.

Перед разработкой прочитайте [AGENTS.md](AGENTS.md). Для актуального состояния конкретной функции проверяйте код, тесты и [GitHub Issues](https://github.com/Troyevv/ai_rpg_engine/issues), а не только README.
